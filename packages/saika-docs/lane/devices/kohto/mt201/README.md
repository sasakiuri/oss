# MT201 受信互換仕様（Saika Lane）

[文書一覧](../../../../INDEX.md)

Saika Lane が `MT201` デバイス設定で受理する入力と、着弾への変換を説明する。メーカーの公式通信仕様ではない。

## 2. Saika 側のシリアル設定

Saika Lane の既定値は次のとおりです。

| パラメーター   | Saika 既定値 |
| -------------- | -----------: |
| ボーレート     |         9600 |
| データビット   |            8 |
| ストップビット |            1 |
| パリティ       |       `none` |

設定値は [`targetDeviceDefinitions.ts`](../../../../../saika-lane/src/main/modules/target/domain/targetDeviceDefinitions.ts) で定義する。接続先は OS が列挙したシリアルポートから選択する。

Saika は接続時と試射・本射の切り替え時に、終端文字なしの ASCII `S` / `R` を送る。

## 3. 受信レコード

### 3.1 フレーミング

[`KohtoFormatParser`](../../../../../saika-lane/src/main/modules/target/infra/parsers/KohtoFormatParser.ts)
は受信バイト列を UTF-8文字列として扱い、LF（`\n`）ごとにレコードを分割する。

- LF まで到着した空でない行を1レコードとして後段へ渡す。
- 空行は無視する。
- 末尾に LF がない断片は `remaining` として保持し、次の受信データとの結合対象にする。
- 行末の CR や行の前後空白は、後段パーサーの `trim()` により除去されるため CRLF も受理できる。

レコードは可変長で、各フィールドを次節の条件で検査する。

着弾音は、行全体の検査・変換が成功すると 1 発につき 1 回鳴る。分割された受信断片や不正な行では鳴らない。音は保存完了の通知ではないため、記録は画面の着弾と得点で確認する。

### 3.2 正規形

次の形式で入力します。

```text
R 9.7 0250 FF5F 70
R10.9 0000 0000 70
```

概念上の構文:

```text
record   = mode, optional-space, score, space, x-hex, space, y-hex, space, check-hex
mode     = "R" | "S"
score    = decimal-number
x-hex    = 4HEXDIG
y-hex    = 4HEXDIG
check-hex = 2HEXDIG
```

- モードと得点の間の空白は省略できる。
- 後続フィールドの間には1文字以上の空白が必要である。
- 座標とチェック欄の16進文字は小文字も受理し、内部では大文字へ正規化する。
- モードは現在の実装どおり大文字 `R` または `S` を使う。
- 送信側は得点を `0.0`〜`10.9` の小数点1桁で生成すること。最終的な範囲検査は Saika の
  `Score` 値オブジェクトが行う。

現在のパーサーは一部の空白や数値表現に寛容だが、それは互換性保証ではない。送信側は上記の正規形を
使い、不正な数値文字列が偶然受理される挙動に依存しない。

### 3.3 フィールド

| フィールド | 受理形式       | Saika での扱い                              |
| ---------- | -------------- | ------------------------------------------- |
| mode       | `R` または `S` | `R` → `MATCH`、`S` → `SIGHTING`             |
| score      | 数値文字列     | `round(score × 10)` で0.1点単位の整数へ変換 |
| x          | 16進4桁        | 符号付き16ビットへ変換後、mm へ変換         |
| y          | 16進4桁        | 符号付き16ビットへ変換後、mm へ変換         |
| check      | 16進2桁        | 形式だけを検査し、`Shot` には保存しない     |

チェック欄は2桁の16進数であることだけを確認する。Saika Lane は現在、値を再計算・照合しない。したがって、この欄が正しく見えても転送データの完全性は保証されない。

## 4. 座標変換

[`MT201CoordinateConverter`](../../../../../saika-lane/src/main/modules/target/adapters/mt201/MT201CoordinateConverter.ts)
は、X と Y を16ビットの2の補数として読み、次の式で Saika の mm 座標へ変換する。

```text
signed = hex < 0x8000 ? hex : hex - 0x10000
millimetres = signed / 150
```

| 16進値 | 符号付き値 | Saika 座標       |
| ------ | ---------: | ---------------- |
| `0000` |          0 | `0 mm`           |
| `0250` |        592 | 約 `3.947 mm`    |
| `FF5F` |       -161 | 約 `-1.073 mm`   |
| `8000` |     -32768 | 約 `-218.453 mm` |
| `7FFF` |      32767 | 約 `218.447 mm`  |

X/Y の符号を現実の左右・上下へ対応させる向きは、設置方向を含む実機側の条件を本書だけでは確定
できない。Saika は受信した X/Y の符号を反転せず、そのまま `ImpactPoint(x, y)` に格納する。

## 5. `Shot` への変換

[`MT201Adapter`](../../../../../saika-lane/src/main/modules/target/adapters/MT201Adapter.ts) は次の順で
レコードを変換する。

1. レコードを `mode`, `score`, `xHex`, `yHex`, `checksum` に分解する。
2. `R` を本射、`S` を試射として、呼び出し元のモードより受信モードを優先する。
3. ミスの特殊値を判定する。
4. 通常ショットの座標を mm へ変換する。
5. 得点を0.1点単位の整数に変換し、`0`〜`109` の範囲を検査する。
6. 種目の標的設計と座標から inner ten を判定し、`Shot` を生成する。

### 5.1 ミス

次の3条件がすべて成立するときだけ、Saika はミスとして扱う。

| score | x      | y      | 生成結果                                   |
| ----- | ------ | ------ | ------------------------------------------ |
| `0.0` | `7FFF` | `7FFF` | 得点0、`impactPoint: null`、inner ten なし |

座標の一方だけが `7FFF`、または得点が0以外の場合は、この特殊判定には入らない。

### 5.2 得点

受信得点を `Math.round(score × 10)` で整数化する。記録時には装置得点を優先し、座標からの計算値も照合用に保持する。インナー 10 は座標から判定する。共通の採点処理は [標的・採点データ](../../../../common/TARGET_SPEC.md#得点の扱い) を参照する。

## 6. エラー条件

次の入力は変換エラーまたは検証エラーになる。

- 必須フィールドが不足している、または余分な非空白文字がある。
- モードが大文字 `R` / `S` 以外である。
- 得点を有限数として解釈できない。
- X/Y が16進4桁ではない。
- チェック欄が16進2桁ではない。
- 変換後の得点が Saika の範囲 `0`〜`109` を外れる。
- 座標から有効な `ImpactPoint` を生成できない。

## 8. 接続時の切り分け

1. Saika 設定で `MT201` と意図したシリアルポートが選択されているか確認する。
2. 設定値が9600 baud、8 data bits、parity none、1 stop bit になっているか確認する。
3. 受信行が LF または CRLF で完結しているか確認する。
4. モード、得点、X、Y、チェック欄が §3 の形式か確認する。
5. 解消しない場合は [問い合わせに必要な情報](../../../../GETTING_STARTED.md#問い合わせに必要な情報) を確認する。

## 9. 検証状態

自動テストは構文検査、座標変換、ショット生成、改行による分割に加え、試射・本射それぞれの分割受信から保存・着弾通知までを対象とする。実機では利用する OS・変換器・機器の組み合わせで、接続、試射・本射の切り替え、連続着弾、再接続を確認する。
