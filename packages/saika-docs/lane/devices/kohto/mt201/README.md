# MT201受信互換仕様（Saika Lane）

この文書は、Saika Laneが `MT201` デバイス設定で受理する入力と、`Shot` への変換方法を説明する
独立実装向けの互換性ノートである。興東電子株式会社の公式通信仕様、取扱説明書、保守手順ではなく、
同社による提携、承認、動作保証を示すものでもない。

内容は、このリポジトリでMIT Licenseにより公開しているSaika Laneの実装・テストと、メーカーの
公開製品ページで確認できる製品識別情報だけを基礎にしている。移植元にあった他製品の解析、
パケットキャプチャ、推定コマンド、未公開資料由来の記述は収録していない。

## 3. 受信レコード

### 3.1 フレーミング

[`KohtoFormatParser`](../../../../../saika-lane/src/main/modules/target/infra/parsers/KohtoFormatParser.ts)
は受信バイト列をUTF-8文字列として扱い、LF（`\n`）ごとにレコードを分割する。

- LFまで到着した空でない行を1レコードとして後段へ渡す。
- 空行は無視する。
- 末尾にLFがない断片は `remaining` として保持し、次の受信データとの結合対象にする。
- 行末のCRや行の前後空白は、後段パーサーの `trim()` により除去されるためCRLFも受理できる。

文字列をバイト数18の固定長としては扱わない。フィールドの意味と受理条件を正とする。

### 3.2 正規形

Saikaのテストfixtureで使う正規形は次である。

```text
R 9.7 0250 FF5F 70
R10.9 0000 0000 70
```

概念上の構文:

```text
record   = mode, optional-space, score, space, x-hex, space, y-hex, space, check-hex
mode     = "R" | "S"
score    = decimal-number
x-hex    = 4HEXDIG
y-hex    = 4HEXDIG
check-hex = 2HEXDIG
```

- モードと得点の間の空白は省略できる。
- 後続フィールドの間には1文字以上の空白が必要である。
- 座標とチェック欄の16進文字は小文字も受理し、内部では大文字へ正規化する。
- モードは現在の実装どおり大文字 `R` または `S` を使う。
- 送信側は得点を `0.0`〜`10.9` の小数点1桁で生成すること。最終的な範囲検査はSaikaの
  `Score` 値オブジェクトが行う。

現在のパーサーは一部の空白や数値表現に寛容だが、それは互換性保証ではない。送信側は上記の正規形を
使い、不正な数値文字列が偶然受理される挙動に依存しない。

### 3.3 フィールド

| フィールド | 受理形式       | Saikaでの扱い                               |
| ---------- | -------------- | ------------------------------------------- |
| mode       | `R` または `S` | `R` → `MATCH`、`S` → `SIGHTING`             |
| score      | 数値文字列     | `round(score × 10)` で0.1点単位の整数へ変換 |
| x          | 16進4桁        | 符号付き16ビットへ変換後、mmへ変換          |
| y          | 16進4桁        | 符号付き16ビットへ変換後、mmへ変換          |
| check      | 16進2桁        | 形式だけを検査し、`Shot` には保存しない     |

チェック欄は2桁の16進数であることだけを確認する。Saika Laneは現在、値の再計算や照合を行わない。
したがって、この欄が正しく見えても転送データの完全性は保証されない。

## 4. 座標変換

[`MT201CoordinateConverter`](../../../../../saika-lane/src/main/modules/target/adapters/mt201/MT201CoordinateConverter.ts)
は、XとYを16ビットの2の補数として読み、次の式でSaikaのmm座標へ変換する。

```text
signed = hex < 0x8000 ? hex : hex - 0x10000
millimetres = signed / 150
```

| 16進値 | 符号付き値 | Saika座標        |
| ------ | ---------: | ---------------- |
| `0000` |          0 | `0 mm`           |
| `0250` |        592 | 約 `3.947 mm`    |
| `FF5F` |       -161 | 約 `-1.073 mm`   |
| `8000` |     -32768 | 約 `-218.453 mm` |
| `7FFF` |      32767 | 約 `218.447 mm`  |

X/Yの符号を現実の左右・上下へ対応させる向きは、設置方向を含む実機側の条件を本書だけでは確定
できない。Saikaは受信したX/Yの符号を反転せず、そのまま `ImpactPoint(x, y)` に格納する。

## 5. `Shot` への変換

[`MT201Adapter`](../../../../../saika-lane/src/main/modules/target/adapters/MT201Adapter.ts) は次の順で
レコードを変換する。

1. レコードを `mode`, `score`, `xHex`, `yHex`, `checksum` に分解する。
2. `R` を本射、`S` を試射として、呼び出し元のモードより受信モードを優先する。
3. ミスの特殊値を判定する。
4. 通常ショットの座標をmmへ変換する。
5. 得点を0.1点単位の整数に変換し、`0`〜`109` の範囲を検査する。
6. 種目の標的設計と座標からinner tenを判定し、`Shot` を生成する。

### 5.1 ミス

次の3条件がすべて成立するときだけ、Saikaはミスとして扱う。

| score | x      | y      | 生成結果                                  |
| ----- | ------ | ------ | ----------------------------------------- |
| `0.0` | `7FFF` | `7FFF` | 得点0、`impactPoint: null`、inner tenなし |

座標の一方だけが `7FFF`、または得点が0以外の場合は、この特殊判定には入らない。

### 5.2 得点

受信得点を `Math.round(score × 10)` で整数化し、Saikaの `Score` に渡す。Saikaは座標から得点を
再計算しない。一方、inner tenは受信得点ではなく、選択中の種目に対応する標的形状と座標から判定する。

## 6. エラー条件

次の入力は変換エラーまたは検証エラーになる。

- 必須フィールドが不足している、または余分な非空白文字がある。
- モードが大文字 `R` / `S` 以外である。
- 得点を有限数として解釈できない。
- X/Yが16進4桁ではない。
- チェック欄が16進2桁ではない。
- 変換後の得点がSaikaの範囲 `0`〜`109` を外れる。
- 座標から有効な `ImpactPoint` を生成できない。

受信データをログへ出す場合は、機器固有情報や大会運用情報が混在していないことを確認し、公開の
issueやfixtureへ実データをそのまま貼らない。

## 8. 接続時の切り分け

1. Saika設定で `MT201` と意図したシリアルポートが選択されているか確認する。
2. 設定値が9600 baud、8 data bits、parity none、1 stop bitになっているか確認する。
3. 受信行がLFまたはCRLFで完結しているか確認する。
4. モード、得点、X、Y、チェック欄が §3 の形式か確認する。
5. 形式が正しいのに拒否される場合は、匿名化した最小fixtureで公開テストを追加する。

OS固有のドライバー導入、権限変更、配線、標的本体の保守は環境と製品資料に依存するため、本書では
一律の管理者コマンドや作業手順を提示しない。
