# BPT-216受信互換仕様（Saika Lane）

この文書は、Saika Laneが興東電子株式会社 `BPT-216` と相互運用するための独立実装ノートである。
メーカーの公式通信仕様、保守資料、動作保証ではなく、同社による提携や承認も示さない。

## 1. 根拠と適用範囲

製品名、検出得点範囲、公式アプリケーションV201の公開状況は、メーカーの
[ビームピストル装置ページ](https://kohto.co.jp/beam04.html) で確認した。ワイヤー形式は、利用者から
相互運用解析用に提供された次の公式Windowsアプリケーションを2026-08-14に静的解析して確認した。

| 項目               | 内容                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 配布ファイル       | `v201.zip`                                                         |
| SHA-256            | `0830e0081f1ca80269e6eadfd8dddf16232e6ecc5638ab1f09e1d48b4ac311ad` |
| SaikaデバイスID    | `BPT216`（BP-217 I/F）                                             |
| 旧設定からの移行ID | `BP216`                                                            |
| Saika対応種目      | `BEAM_PISTOL_10M`                                                  |

旧 `BP216` は1.xでBeam Rifle装置として登録されていたため、保存済み設定のIDを `BPT216` へ移行する際は、
旧種目 `BEAM_RIFLE_10M` を `BEAM_PISTOL_10M` へ、旧競技 `BR60S` または未設定の競技を `BP60` へ移行する。
これにより、起動時に復元されるsessionとBPT-216の接続前種目検証を一致させる。

解析対象の配布物、実行ファイル、マニュアル、逆コンパイル結果はリポジトリへ収録していない。以下は、必要な
相互運用挙動だけを独自に記述したものである。掲載する入力例はすべて合成データであり、実機ログではない。

Saikaはこれとは別に、固定幅フレームを受信する `BPT216_RS232` プロファイルも実装する。このプロファイルは
公式V201の静的解析結果を根拠とするものではなく、実装と自動テストで固定した受理契約として、後続節で
明確に区別して記載する。

## 2. シリアル設定

### 2.1 BP-217 I/F（`BPT216`）

| パラメーター   |     値 |
| -------------- | -----: |
| ボーレート     | 115200 |
| データビット   |      8 |
| ストップビット |      1 |
| パリティ       | `none` |
| フロー制御     |   なし |
| 文字コード     |  ASCII |

標的からホストへのデータは改行区切りである。SaikaはLFを終端として扱い、CRLFも受理する。途中で分割された
行は次の受信チャンクまで保持する。

### 2.2 RS-232C（`BPT216_RS232`）

| パラメーター   |     値 |
| -------------- | -----: |
| ボーレート     |   9600 |
| データビット   |      8 |
| ストップビット |      1 |
| パリティ       | `none` |
| フロー制御     |   なし |
| 文字コード     |  ASCII |

RS-232CプロファイルもLF区切りで受信し、CRLFおよび行端のASCII空白を受理する。途中で分割された行は
次の受信チャンクまで保持する。

## 3. 受信フレーム

### 3.1 BP-217 I/F（`BPT216`）

通常フレームは6個以上のCSVフィールドを持つ。

```text
score,x,y,reserved-1,reserved-2,state[,version]
```

| 位置 | フィールド | Saikaでの扱い                                                       |
| ---: | ---------- | ------------------------------------------------------------------- |
|    0 | score      | `0.0`〜`10.9`、0.1点単位。末尾ゼロ付きの `9.70` / `10.90` も受理    |
|    1 | x          | 符号付き10進整数、単位は0.01mm                                      |
|    2 | y          | 符号付き10進整数、単位は0.01mm                                      |
|  3–4 | reserved   | 意味を推定せず、ショット生成には使用しない                          |
|    5 | state      | `T`（確定着弾）、`R`（Ready）、`B`（軌跡）                          |
|    6 | version    | 任意。X欄が `9999` の状態通知で公式アプリが標的バージョン表示に使用 |

Saikaは第6フィールドが `T` の行だけを着弾パーサーへ渡す。`R`、`B`、不明なstateの行は内容を
パースせず破棄し、軌跡データの保存・描画も行わない。そのため、これらは着弾、採点、着弾音を発生
させない。X欄の `9999` は状態通知の特殊値なので、`T` 行に現れても着弾座標へ変換しない。

得点は0.1点単位の整数へ変換する。公式V201と同じく、1点未満の値は0点に正規化する。座標は次式で
Saikaのmm座標へ変換する。

```text
x_mm = x / 100
y_mm = y / 100
```

座標系はX正が右、Y正が上であり、Saika内のCartesian座標と同じなので符号反転は行わない。

### 合成入力例

```text
0.0,0,0,0,0,R
0.0,120,-80,0,0,B
10.90,123,-456,0,0,T
0.0,9999,0,0,0,R,2.01
```

3行目だけが、10.9点、X=`1.23mm`、Y=`-4.56mm` の着弾になる。

### 3.2 RS-232C（`BPT216_RS232`）

RS-232Cプロファイルは、次の固定幅ASCIIフレームだけを着弾候補として受理する。

```text
P<score> <xHex> <yHex> <checksum>
```

- 0.0〜9.9点では `P 9.9` のように `P` の直後へ空白を置き、10.0〜10.9点では `P10.0` のように
  空白を置かない。得点は0.1点刻みである。
- `xHex` と `yHex` は4桁の16進数で、符号付き16 bit整数として解釈する。単位は0.01mmである。
- `checksum` は2桁の16進数である。`P` からチェックサム直前の区切り空白までのASCII byteを加算し、
  下位8 bitを大文字16進2桁にした値と一致しなければ破棄する。
- 1点未満は0点へ正規化する。座標はBP-217 I/Fと同じく `raw / 100` mmへ変換する。

`P`以外で始まるMT-201形式、桁数が異なるフレーム、不正なチェックサムは着弾として通知しない。

## 4. モードコマンド

Saikaは接続時および試射・本射の切替時に、終端文字なしのASCII 1 byteを標的へ送る。

| Saikaモード | 送信byte |
| ----------- | -------- |
| 試射        | `S`      |
| 本射        | `R`      |

受信フレーム自体には試射・本射の区別がないため、生成する `Shot.mode` にはSaikaの現在モードを使う。

## 5. 標的と採点

`BEAM_PISTOL_10M` は [JRSF_BP_10M](../../../../common/TARGET_SPEC.md#jrsf_bp_10m10m-ビームピストル標的)
を使用する。標的環は10mエアピストルと同じで、仮想弾径4.5mm（半径2.25mm）として描画・座標採点
する。BPT-216が通知した得点は `deviceScore` として保持し、BP60では整数圏採点を適用する。

## 6. MT-201とのシグナル受信・処理比較（BP-217 I/F）

次の表はメーカー通信仕様同士の比較ではなく、Saika Laneの現在の受信・変換経路を処理段階ごとに
比較したものである。MT-201については公開済みSaika実装の挙動、BPT-216のBP-217 I/Fプロファイルについては
同実装に加えて公式V201の相互運用解析で確認した範囲を記載する。RS-232Cプロファイル固有の差異は
§2.2および§3.2を参照する。

| 処理段階               | MT-201（Beam Rifle）                                                                                         | BPT-216 BP-217 I/F（Beam Pistol）                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 対応種目               | `BEAM_RIFLE_10M`                                                                                             | `BEAM_PISTOL_10M`                                                                                  |
| シリアル設定           | 9600 baud、8N1                                                                                               | 115200 baud、8N1、フロー制御なし                                                                   |
| Saika内の受信経路      | `SerialPort` → `DirectSerialTargetProtocol` → `USBDataPipeline` → `SerialDataParser` → `KohtoFormatParser`   | `SerialPort` → `BPT216TargetProtocol` → `BPT216ProtocolSession` → `USBDataPipeline`                |
| レコード境界           | LF。CRLFはMT-201パーサーの`trim()`で受理                                                                     | LF。専用セッションがCR、空白、タブを行端から除去するためCRLFも受理                                 |
| 未完行の保持           | 次のチャンクまで保持。受信間隔が1秒以上空くと破棄し、全体が1MiBを超えるとエラー                              | 次のチャンクまで保持。タイムアウトは設けず、未完行または1行が4096 byteを超えると破棄               |
| 着弾レコード形式       | 空白区切りの `mode score xHex yHex checksum`                                                                 | CSVの `score,x,y,reserved-1,reserved-2,state[,version]`                                            |
| 着弾前の選別           | 完結した空でない行をすべてMT-201パーサーへ渡し、`R` / `S`だけを着弾として受理                                | 第6フィールドが`T`の行だけを着弾パーサーへ渡す                                                     |
| 非着弾シグナル         | Ready・軌跡・状態通知という分類は持たない。不正レコードは変換エラー                                          | `R`、`B`、不明stateは内容をパースせず破棄。軌跡の保存・描画もしない                                |
| 試射・本射の決定       | レコード先頭の`R`を`MATCH`、`S`を`SIGHTING`として、Saikaの現在モードより優先                                 | 受信`state`は試射・本射を表さない。Saikaの現在モードを`Shot.mode`に使用                            |
| ホストからのモード送信 | MT-201プロトコルは終端なしの`S` / `R` 1 byteを送信する。ただし、実機側での正式な意味と適合性は本書では未確定 | BPT-216プロトコルは公式V201の挙動に合わせ、試射=`S`、本射=`R`を終端なしで送信                      |
| 得点の受理             | 数値を`round(score × 10)`で0.1点単位へ変換し、`0`〜`109`を検査                                               | `0.0`〜`10.9`の0.1点単位だけを受理。`9.70`のような末尾ゼロは許容し、1点未満は0点へ正規化           |
| 60発競技での得点       | BR60Sは`DECIMAL`採点なので、受信した小数点得点を保持・表示                                                   | BP60は`RING`採点なので小数点以下を切り捨てて記録し、競技画面では整数表示。印刷帳票は小数形式も併記 |
| 座標表現・変換         | 16進4桁を符号付き16 bitとして解釈し、`raw / 150` mm                                                          | 符号付き10進整数を解釈し、`raw / 100` mm                                                           |
| X/Yの向き              | 受信した符号を反転せず使用                                                                                   | X正を右、Y正を上として符号を反転せず使用                                                           |
| ミス・状態特殊値       | `score=0.0`かつ`x=y=7FFF`だけを座標なしのミスにする                                                          | 1点未満は0点だが座標は保持する。X欄`9999`は状態通知なので着弾へ変換しない                          |
| 付加フィールド         | checksumは16進2桁の形式だけを検査し、再計算・照合はしない                                                    | reserved欄は使用しない。version欄は任意で、チェックサム欄はない                                    |
| inner ten              | 受信得点ではなく、Beam Rifleの標的形状と変換後座標から判定                                                   | 受信得点ではなく、Beam Pistolの標的形状と変換後座標から判定                                        |
| 着弾通知・着弾音       | パース前に受信チャンク単位で通知する。不完全・不正チャンクでも通知され、1チャンクに複数行ある場合も通知は1回 | `T`行の構文・座標・種目検査に成功した後、着弾ごとに通知する。`R` / `B` / 不正`T`では通知しない     |
| ショット番号           | 変換に成功した着弾ごとに増加。不正レコードでは増加しない                                                     | 変換に成功した`T`着弾ごとに増加。破棄したstateや不正`T`では増加しない                              |
| 種目整合性の防御       | デバイス定義でBeam Rifleだけを選択可能にする。専用受信セッションでの再検査はない                             | 接続時と各`T`着弾の処理前に、現在種目がBeam Pistolであることを再検査                               |

要点は、MT-201が「改行で完成した行を汎用パイプラインへ渡し、行内の`R` / `S`をショットモード
として解釈する」のに対し、BPT-216は「専用受信セッションが`T`だけを選別し、Saika側の現在モードで
ショットを生成する」点にある。したがって、両機種は同じ`KOHTO`メーカー分類でも受信パーサーを共有
しない。接続・停止・モード送信という共通操作だけを `TargetProtocol` 境界で揃え、wire形式は各実装へ
閉じ込める。
