# DISAG RedDot 受信互換仕様（Saika Lane）

[文書一覧](../../../../INDEX.md)

Saika Lane が RedDot の RS-232 接続で受理する形式、接続時の初期化、着弾への変換を説明します。メーカーの公式通信仕様ではありません。掲載フレームは合成データです。

## 1. 対応範囲と検証状態

Saika は次の 2 プロファイルを実装しています。どちらもモデル名は `KT RDT ZIE 1`、メーカー選択は「DISAG」です。末尾の Rifle・Pistol は Saika の設定区分です。

| デバイス ID                 | 対応種目         | 標的          | 初期化時の種別値 |
| --------------------------- | ---------------- | ------------- | ---------------- |
| `DISAG_KT_RDT_ZIE_1_RIFLE`  | `AIR_RIFLE_10M`  | `ISSF_AR_10M` | `01`             |
| `DISAG_KT_RDT_ZIE_1_PISTOL` | `AIR_PISTOL_10M` | `ISSF_AP_10M` | `00`             |

接続前と各着弾の処理前に、選択した機器と現在の競技種目が一致するか検査します。不一致やセッション終了時は接続エラーとして停止します。旧設定の `RDT_ZIE1_RIFLE` / `RDT_ZIE1_PISTOL` は上記の ID とメーカー `DISAG` へ移行します。

両プロファイルとも **実装済み・実機検証待ち** です。合成データによる自動テストと、機器を接続した運用確認は区別します。Bluetooth、校正、保守、ファームウェア更新は本書の対象外です。

## 2. 接続設定

Lane で対応する競技種別を選び、「Settings」→「Connection」でポートと RedDot のプロファイルを選択します。一般的な操作は [Lane 操作ガイド](../../../README.md#標的装置へ接続する) を参照してください。

| 項目                          | Saika の設定値                                 |
| ----------------------------- | ---------------------------------------------- |
| ボーレート                    | 9600                                           |
| データビット / ストップビット | 8 / 1                                          |
| パリティ                      | なし                                           |
| RTS/CTS・XON/XOFF フロー制御  | 無効                                           |
| DTR / RTS                     | ポートを開いた後、設定可能な環境では無効にする |

PC 直結の配線は、メーカーの [旧版技術説明書](https://www.disag.de/download/manuals/reddot_laserziel.pdf) 6 ページでは D-Sub の 2→2、3→3、5→5 と示されています。[取扱説明書](https://www.disag.de/wp-content/uploads/reddot_laserziel.pdf) 14 ページのクロス配線は、LAN 対応 OpticScore 測定枠への接続用です。接続相手と変換器を含めた配線を確認してください。

以下の通信値と待ち時間は Saika の実装値です。メーカー保証値を示すものではありません。

## 3. 接続時の初期化

Saika は接続・再接続のたびに次の順で初期化します。送信処理は直列に実行し、各送信の完了（`drain`）を待ちます。

1. 最初に `ENQ`（`05`）を送り、応答を待つ。
2. 単独の `NAK`（`15`）、フレーム受信、または 300 ms の無応答で初回確認を終える。
3. 標的種別設定コマンド `11 00 01` を 1 回送る。
4. 単独の `ACK`（`06`）を最大 500 ms 待つ。
5. `ACK` を確認したら Rifle は `01`、Pistol は `00` を 1 バイト送る。
6. 追加の `ACK` は待たず、初期化を完了して 100 ms 後の問い合わせを予約する。

標的種別設定の `ACK` が来なかった場合は、プロファイルごとに扱いが異なります。

| プロファイル | 応答がない場合                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------- |
| Rifle        | `01` を 1 回送り、500 ms 待って遅延応答を消費した後、従来の問い合わせ方式を開始する。警告を残す |
| Pistol       | `RED_DOT_INITIALIZATION_FAILED` で接続を失敗させる                                              |

`11 00 01` は再送しません。応答だけが失われた場合、標的が次の 1 バイトを種別値として待っている可能性があるためです。Pistol は Rifle の設定のまま採点されることを避けるため、応答を確認できない状態で接続を完了しません。

初期化前に受信を始めたフレームは、正常なら `ACK` を返しますが、着弾として記録しません。初期化後に残りのデータが届いた場合も同様です。接続完了を確認してから射撃を始めてください。

両プロファイルとも受信フレームの種別は `LG` です。この値だけで Rifle と Pistol を区別できません。

## 4. 接続後の通信と復旧

Saika は `ENQ` で送信待ちデータを問い合わせます。RedDot へ ASCII の `S` / `R` は送りません。試射・本射の区分は Lane の現在のモードを使います。

| 受信・状態           | Saika の処理                                                                 |
| -------------------- | ---------------------------------------------------------------------------- |
| 単独の `NAK`         | データなしとして扱い、次の問い合わせを予約する。着弾・音・エラーは発生しない |
| 正常フレーム         | `ACK` の送信完了後に着弾処理へ渡し、次の問い合わせを予約する                 |
| 不正フレーム         | `NAK` を送り、警告を記録して応答を待つ                                       |
| 300 ms の無応答      | 未完フレームを破棄して警告を記録し、次の問い合わせを予約する                 |
| 送信失敗             | 接続エラーにする。`ACK` 送信に失敗したフレームは着弾処理へ渡さない           |
| ポートの切断・エラー | 通信処理を停止し、旧ポートを閉じてから既存の再接続処理へ進む                 |

次の問い合わせは通常 100 ms 後です。応答を待っている間に重複する `ENQ` は送りません。不正応答が 3 回続くと、残りの受信候補を破棄して次の問い合わせへ進みます。初期化中の不正フレームは初期化の待ち時間を延長しません。

初期化後は、`ENQ` の応答待ちでなくても正常フレームを受理します。受信後は問い合わせの予約を張り直します。同じ座標・得点の連射も有効なため、内容や着弾間隔による重複排除は行いません。

### 受信の分割と再同期

シリアル受信の 1 回分とフレームの境界は一致しません。Saika は分割されたフレームを結合し、連結された複数フレームを順番に読みます。

- `STX` から 59 バイト揃うまで追加受信を待つ。
- ノイズは次の `ACK`、`NAK`、`STX` まで破棄する。ノイズだけでは `NAK` を返さない。
- 固定制御位置が不正な候補は、候補内の次の `STX` まで破棄する。なければ候補 59 バイト全体を捨てる。
- 構造が正しくても BCC やフィールドが不正なら、候補 59 バイト全体を捨てる。
- 不正候補内の `ACK` / `NAK` 相当値を、単独の制御応答として解釈しない。

受信バッファーの上限は 4096 バイトです。超過時は最後の `STX` 以降が上限内なら残し、それ以外は全消去して警告を記録します。

## 5. 59 バイト フレーム

オフセットは 0 始まり、範囲は両端を含みます。制御値は 16 進数です。BCC を含むため、フレーム全体を文字列へ変換せずバイト列として扱います。

| offset | 長さ | 名前         | 形式・必須値                  |
| -----: | ---: | ------------ | ----------------------------- |
|      0 |    1 | `stx`        | `0x02`                        |
|    1–8 |    8 | `reservedA`  | printable ASCII、意味は未規定 |
|      9 |    1 | `cr1`        | `0x0D`                        |
|  10–17 |    8 | `reservedB`  | printable ASCII、意味は未規定 |
|     18 |    1 | `cr2`        | `0x0D`                        |
|  19–20 |    2 | `discipline` | ASCII `LG`                    |
|     21 |    1 | `cr3`        | `0x0D`                        |
|  22–23 |    2 | `reservedC`  | printable ASCII、意味は未規定 |
|     24 |    1 | `cr4`        | `0x0D`                        |
|  25–27 |    3 | `reservedD`  | printable ASCII、意味は未規定 |
|     28 |    1 | `cr5`        | `0x0D`                        |
|  29–30 |    2 | `reservedE`  | printable ASCII、意味は未規定 |
|     31 |    1 | `cr6`        | `0x0D`                        |
|  32–35 |    4 | `score`      | ASCII `dd.d`、`00.0`〜`10.9`  |
|     36 |    1 | `cr7`        | `0x0D`                        |
|  37–42 |    6 | `distance`   | ASCII `dddd.d`                |
|     43 |    1 | `cr8`        | `0x0D`                        |
|  44–48 |    5 | `x`          | ASCII `[+-]dddd`              |
|     49 |    1 | `cr9`        | `0x0D`                        |
|  50–54 |    5 | `y`          | ASCII `[+-]dddd`              |
|     55 |    1 | `cr10`       | `0x0D`                        |
|     56 |    1 | `etb`        | `0x17`                        |
|     57 |    1 | `bcc`        | 次節で算出する 1 バイト       |
|     58 |    1 | `terminator` | ASCII `$`、`0x24`             |

予約領域 `reservedA`〜`reservedE` は、各 byte が `20`〜`7E` の ASCII であることだけを検査します。値を入力例と同じにする必要はありません。正式な意味は未確認です。

得点・距離・座標は表の桁数、符号、小数点位置で検査します。制御位置、BCC、種別、数値のどれかが不正なら着弾として通知しません。

### BCC の計算

オフセット 0 の `STX` から 56 の `ETB` までの 57 バイトを XOR します。結果が `20` 未満なら `20` を加算します。BCC 自身と末尾の `$` は計算に含めません。

```ts
function calculateRedDotBcc(bytesThroughEtb: Uint8Array): number {
  let value = 0;
  for (const byte of bytesThroughEtb) value ^= byte;
  return value < 0x20 ? value + 0x20 : value;
}
```

## 6. 座標・得点への変換

原点は標的中心、X は右が正、Y は上が正です。受信した座標の符号は反転しません。

```text
scoreTenths = 得点の整数部 × 10 + 小数 1 桁
xMm = xRaw / 100
yMm = yRaw / 100
distanceMm = distanceRaw / 100
```

X/Y の単位は 0.01 mm です。距離欄は raw 値の小数第 1 位まであるため、換算後は 0.001 mm まで表現できます。いずれも測定精度を意味しません。

`abs(distanceRaw - hypot(xRaw, yRaw)) > 0.100001` なら警告を記録します。構造と BCC が正しければ受理し、座標を距離欄から補正しません。

| 記録する項目      | 扱い                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| 装置得点          | フレームの得点を保持する。座標計算値との差だけでは拒否しない           |
| 標的・インナー 10 | 選択した Rifle / Pistol の標的を使って座標から判定する                 |
| 試射・本射        | フレームに含まれないため、Lane の現在モードを使う                      |
| 受信時刻          | 59 バイト が揃い、構造検査を始めた時刻。`ACK` 完了時刻には置き換えない |
| 0 点              | 有効な X/Y があれば座標付きの 0 点として扱う                           |

座標なしを示す機器固有の特殊値は未確認です。標的の寸法と採点式は [標的・採点データ](../../../../common/TARGET_SPEC.md) を参照してください。

## 7. エラーの確認

初期化結果はデバッグパネルとログファイルに記録します。画面の開き方とファイルの保存場所は [ログの確認手順](../../../README.md#ログを確認する) を参照してください。

| コード                               | 意味・対応                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| `RED_DOT_TARGET_TYPE_CONFIGURED`     | 標的種別の設定を完了した                                                             |
| `RIFLE_LEGACY_POLLING_FALLBACK`      | 種別設定の応答を確認できず、Rifle の従来方式で接続した。選択種目と装置得点を確認する |
| `RED_DOT_INITIALIZATION_FAILED`      | Pistol の初期化に失敗した。機器・ポート・接続設定を確認する                          |
| `FRAME_BEFORE_TARGET_TYPE_DROPPED`   | 初期化前に受信した着弾を記録しなかった                                               |
| `INVALID_BCC` / `INVALID_DISCIPLINE` | チェックサム不一致、または `LG` 以外のフレームを受信した                             |
| `DISTANCE_MISMATCH`                  | 座標と距離欄に差がある。受信フレーム自体は受理した                                   |

接続を復旧できない場合は [問い合わせに必要な情報](../../../../GETTING_STARTED.md#問い合わせに必要な情報) を確認してください。公開する資料には実射データや機器固有情報を含めません。

## 8. 合成入力例

### 正常フレーム

次の例は X=3 mm、Y=4 mm、距離=5 mm の合成データです。

```text
<STX>00000000<CR>00000000<CR>LG<CR>01<CR>1.0<CR>01<CR>09.0<CR>0500.0<CR>+0300<CR>+0400<CR><ETB>:$
```

59 バイトの 16 進表現は次のとおりです。

```text
0230303030303030300d30303030303030300d4c470d30310d312e300d30310d30392e300d303530302e300d2b303330300d2b303430300d173a24
```

| 項目                | 期待値                       |
| ------------------- | ---------------------------- |
| BCC                 | `3A`                         |
| 得点                | 9.0 点（`scoreTenths = 90`） |
| 座標                | X=3.00 mm、Y=4.00 mm         |
| 距離                | 5.000 mm                     |
| Rifle のインナー 10 | `false`                      |

Pistol のテストでは、同じフレームの得点を `10.3` に変更して BCC を再計算します。装置得点は `103`、座標は同じです。中心距離 5.00 mm は AP の境界 4.75 mm より外なので、インナー 10 は `false` です。

### 負の座標を含むフレーム

```text
0230303030303030300d30303030303030300d4c470d30310d312e300d30310d31302e310d303232332e360d2b303130300d2d303230300d173124
```

全長は 59 バイト、BCC は `31` です。期待値は得点 10.1 点、X=1.00 mm、Y=-2.00 mm、距離=2.236 mm です。
