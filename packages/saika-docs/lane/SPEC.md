# Lane 製品仕様

[Lane 操作ガイド](./README.md)

操作ガイドを補う外部仕様です。画面で確認できる状態、入力の制約、記録と出力の扱いを説明します。使用する版の [競技種別定義](../common/COMPETITION_TYPES.md) と併せて参照してください。

## 動作環境と対応機器

Windows 10 / 11の x64を主な動作対象とし、macOS・Linux は実験対象です。標的装置1台に対して Lane を1つ起動し、同時に接続するシリアルポートは1つです。MQTT を無効にしても、標的への接続、着弾の記録・表示、単独の競技進行、印刷を利用できます。

配布版は同梱の画面を使用し、開発用サーバーの設定を参照しません。

「Connection」で選択できる機器は次のとおりです。全機器でデータビット8、ストップビット1、パリティなしを使用します。

| メーカー          | 装置 / ID                                   | ボーレート | 実装・検証状態         |
| ----------------- | ------------------------------------------- | ---------: | ---------------------- |
| Kohto Electronics | MT201 / `MT201`                             |       9600 | 受信・座標変換に対応   |
| Kohto Electronics | BPT-216（`BP-217 I/F`）/ `BPT216`           |     115200 | 実装済み、実機検証待ち |
| Kohto Electronics | BPT-216（RS-232C）/ `BPT216_RS232`          |       9600 | 実装済み、実機検証待ち |
| DISAG             | RedDot Rifle / `DISAG_KT_RDT_ZIE_1_RIFLE`   |       9600 | 実装済み、実機検証待ち |
| DISAG             | RedDot Pistol / `DISAG_KT_RDT_ZIE_1_PISTOL` |       9600 | 実装済み、実機検証待ち |

SIUS、Meyton、Custom は内部定義を持ちますが、現行の接続画面には表示しません。競技種別の登録と、実機での受信・標的信号の出力は別の対応範囲です。

受理するデータ、単位、通信異常への対応は機器ごとの仕様にまとめています。

- [MT201 受信互換仕様](./devices/kohto/mt201/README.md)
- [BPT-216 受信互換仕様](./devices/kohto/bpt216/README.md)
- [DISAG RedDot 受信互換仕様](./devices/disag/reddot/README.md)

## 設定項目と反映時点

「Settings」は6つのタブで構成されます。初回起動時の射座番号は `1`、音量は `50`、競技種別は `BR60S` です。MQTT は無効で、自動接続も無効です。

| 場所・項目                   | 入力・制約                                                  | 反映と保存                                                             |
| ---------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| General / Lane Number        | 1以上の整数                                                 | 「Save」で保存し、次回起動時にも使用                                   |
| General / Shot Sound Volume  | 0〜100の整数。0は無音                                       | 「Test sound」で確認し、「Save」で保存                                 |
| General / Application Update | 更新状態を表示                                              | ダウンロード後の「Restart & Install」で適用                            |
| General / Shot timing        | 受信遅延・時計の不確かさ。各 0〜60000 ms の整数、空欄は不明 | 競技終了後に「Save shot timing」または保存済みプロファイルの適用で反映 |
| Target                       | 登録済み競技種別から選択                                    | 選択時に新しい競技とセッションを作成し、最初のステージを開始           |
| Connection                   | ポート、メーカー、装置                                      | 接続成功時の設定を保存し、次回起動時に再接続を試行                     |
| MQTT                         | 有効化、Broker URL、Lane Alias、Auto Connect                | 「Save Settings」で保存。「Connect」・「Disconnect」で接続を操作       |
| Printing                     | プリンター、用紙、向き、部数、カラー、片面・両面            | 「Save Printing Settings」で保存。出力先指定時は直接印刷               |
| JSON                         | `settings.json` 全体                                        | 形式と値を検査して保存。不正な入力は拒否                               |

競技種別の選択は閲覧操作ではありません。現在の記録を印刷したい場合は、選択する前に印刷してください。MQTT の Lane ID は端末の識別子で、射座番号・Lane Alias とは別です。JSON で空の ID を保存した場合も、既存の安定した ID を維持します。

### 計時測定データとプロファイル

「Settings」→「General」の「Shot timing」で、標的時間制御に使う判定方法を選びます。

| Timing assessment          | 動作                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------ |
| Review uncertain timing    | 受信遅延と時計の不確かさを考慮し、射撃可能時間の境界にかかる着弾などを確認対象にする |
| Use the supplied timestamp | 受信遅延と時計の不確かさを考慮せず、与えられた時刻を使う                             |

初期値は「Review uncertain timing」で、両方の上限値は不明です。不明な値は空欄のままにします。手入力の値は「Save shot timing」で保存します。これらの設定で射撃可能時間は延長されません。

「Measured timing profiles」では、手入力した上限値または測定 JSON から設定を保存できます。作成・適用は [次節の手順](#測定プロファイルを作成して適用する) を参照してください。

測定 JSON は UTF-8 の配列です。上限は 262,144 バイト、2,000 サンプルです。次は形式を示す合成データであり、実際の設備の推奨値ではありません。

```json
[
  { "kind": "RECEIPT_DELAY", "valueMilliseconds": 12.4, "uncertaintyMilliseconds": 0.6 },
  { "kind": "CLOCK_OFFSET", "valueMilliseconds": -2.1, "uncertaintyMilliseconds": 0.4 }
]
```

`RECEIPT_DELAY` は非負の受信遅延、`CLOCK_OFFSET` は符号付きの時計差です。単位は ms で、各測定の不確かさも必須です。時計差は ±60000 ms、受信遅延・不確かさ・余裕は 0〜60000 ms の範囲です。空配列や、計算した上限値が 60000 ms を超える入力は拒否します。

種別ごとに `abs(valueMilliseconds) + uncertaintyMilliseconds` の最大値を取り、指定した余裕を加えて整数へ切り上げます。上の例で両方の余裕を 1 ms とすると、候補は受信遅延 14 ms、時計の不確かさ 4 ms です。サンプルのない種別は不明のままです。

解析は設定を変更しません。保存時に再計算し、入力原文・SHA-256・計算方式・余裕を残します。適用は競技終了後の別操作です。測定した範囲からの推定値なので、設備の運転条件を含む測定かどうかを担当者が確認します。

### 測定プロファイルを作成して適用する

測定証拠を使う場合は、機器と時計の構成を確認し、次の順でプロファイルを作成・適用します。

1. 「Settings」→「General」の「Shot timing」で「Load measured timing profiles」を押す。
2. 「Timing official」に担当者を入力する。構成の初回登録や変更は「Record an equipment or clock setup change」を開き、内容を入力して「Record changed installation」で記録する。
3. 「Save a new measured profile」を開く。「Profile bounds source」で「Measurement data with explicit margins」を選ぶ。
4. 測定 JSON を読み込み、受信遅延と時計差の余裕を ms 単位で入力する。「Analyze timing measurements」を押し、サンプル数と計算値を確認する。
5. プロファイル名、設備構成、測定資料の参照、測定日時を入力する。開始条件で測定証拠を必須にする場合は有効期限も指定し、「Save timing measurement」で保存する。
6. 「Timing profile」で保存した項目を選ぶ。現在の構成との一致を確認してチェックを付け、「Apply selected timing profile」を押す。

「Measured timing profile applied.」と適用値を確認してください。解析・保存だけでは適用されません。機器・配線・時計を変更した後は、構成を記録し直して新しい測定を保存します。競技中や構成不一致で拒否された場合は、原因を解消してから読み直します。

Director で測定証拠を開始条件にする操作は [開始前の運用設定](../director/OPERATIONS.md#開始前の運用設定) を参照してください。

## 接続状態と異常時の動作

標的と MQTT の接続は独立しています。右下の接続アイコンは標的の状態を示し、MQTT の状態は「Settings」→「MQTT」で確認します。

| 状況                     | 表示・動作                                                      | 次の操作                                              |
| ------------------------ | --------------------------------------------------------------- | ----------------------------------------------------- |
| ポート・装置の選択が不足 | 接続ボタンが無効                                                | 必要な項目を選択                                      |
| 標的へ接続中             | 接続処理中の表示                                                | 完了またはエラーを待つ                                |
| 標的へ接続成功           | 「Disconnect」と接続済み表示                                    | 種目と着弾を確認                                      |
| 接続失敗                 | Connection タブにエラー                                         | ポート、電源、ケーブル、装置を確認して再接続          |
| 予期しない標的切断       | 接続設定を開ける警告を表示。旧ポートの終了後に1回だけ自動再接続 | 復旧しなければ Connection タブから接続                |
| MQTT 切断                | 遠隔操作・配信ができなくなる。ローカルの記録は継続              | 同じブローカーへ再接続し、Director 担当者と状態を確認 |

標的切断や MQTT 切断だけでは、競技タイマーは停止しません。中断が必要な場合は、役員の判断と Director の中断操作が必要です。更新・設定保存の失敗は、その操作領域のエラーを確認します。通信や変換の詳細は [ログの確認手順](./README.md#ログを確認する) を参照してください。

## 競技の状態と操作

単独使用の通常進行を示します。選手による標的モード選択は、下記の対象シリーズで優先します。ボタンは現在の状態に応じて有効・無効が変わります。Director の競技への参加中は、進行操作と Target の競技種別選択を Lane 画面で無効にします。Preparation / Match / Next Stage（End Preparation / Advance を含む）とテンキー `1` / `2` / `3` は確認画面を開かず、進行を変更しません。無効なボタンのツールチップと読み上げ用の説明に「Competition progress is controlled by Director」を含めます。

参加状態は通信状態と独立し、切断や競技終了だけでは解除しません。Director の `leave-competition` 成功時、または再接続後の参加状態の復元失敗時にロックを解除します。Lane にローカルの解除操作はありません。初回の参加照会が完了するまでは操作を無効にします。失敗時は無効を維持し、理由を「Director membership could not be loaded」に切り替えてログへエラーを記録します。照会と変更通知の順序が前後しても新しい参加状態を保持します。ズーム、全画面、印刷、役員への連絡、ほかの設定は制限しません。

```mermaid
flowchart TB
  ready[開始待ち] -->|Preparation| sighting[Preparation / 試射]
  sighting -->|Match| match[Match / 本射]
  match -->|上限射数または時間満了| complete[Series Complete]
  complete -->|Advance| next[Next Series / Next Stage]
  next -->|Match| match
  complete -->|最後の Advance| finished[Finished]
```

| 表示・状態                 | 操作・条件                 | 結果                                             |
| -------------------------- | -------------------------- | ------------------------------------------------ |
| 開始待ち                   | Preparation                | 先頭の試射ステージを開始                         |
| Preparation                | Match                      | 試射を終了し、本射へ移行                         |
| Preparation                | End Preparation            | 試射を終了して待機。Advance、Match で本射へ進む  |
| Match                      | 規定射数への到達・時間満了 | シリーズ完了を表示                               |
| Series Complete            | Advance                    | 次シリーズ・次ステージの開始待ち、または競技終了 |
| Next Series / Next Stage   | Match                      | 次のシリーズを開始                               |
| 射撃中                     | Preparation                | 新しいセッションに切り替え、開始待ちへ戻る       |
| シリーズ完了・切り替え待ち | Preparation                | 新しいセッションで先頭ステージを開始             |
| Finished                   | Target で競技種別を選択    | 新しい競技を作成                                 |

「Preparation」で新しいセッションへ切り替える際は、現在のセッションのいずれかのシリーズに着弾があれば確認する。確定すると元のセッションを終了済みとして保存する。開始待ちからの開始と、着弾のないセッションの切り替えは確認しない。「Match」は、射撃中の試射に着弾があり、試射を終了して本射へ進む場合だけ確認する。次シリーズの開始など、ほかの進行では確認しない。競技の進行を使わないモード切り替えでは、現在のシリーズに着弾があれば Preparation・Match ともに確認する。

確認画面はボタンとテンキー `1` / `2` で共有する。キーの繰り返しではない `Enter`（テンキーも可）または Confirm で確定し、ほかのキー、Cancel、閉じるボタン、ダイアログの外側のクリック、確認を開いて5秒間回答しない場合に取り消す。取消しに使ったキーは通常のショートカットを実行しない。長押しの繰り返しイベントは確定・取消しの対象にしない。確定した Enter を離すまで、その繰り返し入力は受け付けない。確認中も着弾を表示し、競技 ID・セッション ID・進行状態や Director への参加状態が変われば実行せず閉じる。

「Preparation」による記録の切り替えは、一時停止や再開とは異なります。25m の標的時間制御と決勝の進行は [Director 運用ガイド](../director/OPERATIONS.md) を参照してください。

### 選手による標的モード選択

ACTIVE で Rule Pack の `targetModeControl` が `ATHLETE` のシリーズでは、ボタンとテンキー `1` / `2` を Sighting / Match の選択に使います。Director 参加中の進行制限と、単独使用の再開始確認より優先し、確認せず即時に選択します。`3` の進行操作は通常の制限を維持します。

最初の本射を記録するまでは Sighting を選べます。本射を記録した後は Sighting を無効にし、理由を表示します。`1` で Preparation の再開始へ戻ることはありません。Match の再選択は進行を変えません。`POSITION_CHANGE_AND_SIGHTING` は Sighting 専用です。Sighting の禁止時と Match を選べない姿勢変更中は、無効なボタンのツールチップにも理由を表示します。

対象は ACTIVE の採点対象で `targetModeControl: ATHLETE` のシリーズです。`purpose` が `POSITION_CHANGE_AND_SIGHTING` の区間は除きます。Lane の選択があるか、現在の競技・ステージ・シリーズに通常の ATHLETE 判定による Sighting 着弾がある場合を、切り替え済みとします。別の保持フラグは使いません。条件を満たすまでは Match を無効にし、「Switch to Sighting before selecting Match.」を表示します。`2` は何も変更しません。試射なしの `1` → `2` も許可します。

切り替え前の Match 着弾（報告モードなしの場合を含む）は `NULLIFIED_POSITION_EXTRA` の観測資料にし、規則と前のシリーズの姿勢を記録します。Shot、射順、得点、射数、進行を増やしません。同じ受信処理内で選択 Sighting を保存して既存経路で装置へ指示し、その後に「Extra shot nullified. Target reset to Sighting.」を通知します。続く受信フレームは試射として扱います。無効弾のあるシリーズの履歴だけに「Reported mode」を表示します。MT201 はフレームのモードを解釈します。ほかのアダプターでは Lane の指示値を使うため、装置状態の証拠にはなりません。リセット通知は次のモード選択の成功または進行通知で消します。無効弾の装置点も種目の採点方式に従って表示します。履歴照会は無効弾を `nullifiedExtras` として返し、画面は通常の履歴と受信時刻順に並べます。無効弾の射順は「—」、表示は「Not scored · ISSF 6.10.4(c) / 7.7.3」です。

Sighting のリセット保存に失敗しても、同じ観測へ処理失敗の結果を追加しません。無効弾の記録を維持し、画面にリセット失敗を表示します。シリーズは Sighting の選択が必要なままです。選手が Sighting を選ぶか、さらに届いた Match 着弾を無効にする受信処理でリセットを再試行します。

着弾の保存後は、競技の進行保存を待ってから成功通知します。進行処理が失敗した場合は保存済みの着弾を保持し、成功通知を送らず、役員への連絡を求めるエラーを画面に残します。対応する観測資料には処理失敗を記録します。

シリーズ開始時は Lane の選択なしとし、受信処理の報告モード、報告がなければ Match を使います。選択後は報告モードより Lane の選択を優先し、既存の装置モード送信経路で通知します。本射を記録した後は、報告モードが Sighting でも Match として記録します。セッション、進行位置、射数、得点、タイマーは選択操作で変えません。

選択は競技集約に保存します。自動シリーズ移行でも、実効モードが変わる場合に限り装置へ送信します。シリーズ終了・時間満了・自動移行・巻き戻し・リセット・競技終了で解除し、時計の更新では保持します。接続の復旧時は既存のモード再送経路を使います。予備射座への移動では、通常の ATHLETE 判定を使った着弾の観測を引き継ぎ、そのモードを端末と表示へ復元します。明示的な選択は解除するため、試射を撃たずに移動した場合は移動先で Sighting から再選択します。無効弾は移動元の送信待ち資料に残り、移動先の履歴へは転送しません。移動元が再接続しなければ、その資料は Director に届きません。本射記録前の対象シリーズで役員が無制限の試射を許可した場合は、選択を Sighting として保存します。本射再開後も選手が `2` を押すまで Sighting を維持し、その最初の本射を切り替え忘れとして扱いません。役員が中断中に許可した試射を端末・Lane・Vista で共通に優先します。追加試射が実行中の場合は Sighting / Match の両方を無効にし、「Official sighting is in progress」を表示します。通常の PAUSED / RESUME_PENDING と再起動停止中は、選手の標的モード選択を現在のシリーズの規則に従って許可します。モード選択で時計や競技進行は再開しません。

画面はメインプロセスの射撃モード判定から選択可否・選択値・実効モードを取得します。実効表示は、試射専用、本射記録済み、Lane の選択、現在のシリーズで通常の ATHLETE 判定を使った着弾、Match の順に決めます。中断復旧やシュートオフで試射扱いにした着弾は、装置モードの観測に使いません。Vista は対応する競技で同じ通常モード判定を使い、選択時に表示を更新します。フェーズ・進行・着弾・中断状態の通知で再取得し、古い応答を破棄します。ACTIVE で投影を取得できていない間は、照会失敗時もモード操作を無効にします。次の通知やモードボタン・テンキー `1` / `2` で再照会し、取得後にあらためて選択します。本射ステージの合計・シリーズ点・平均は本射だけから集計します。確認中にシリーズ位置や選択可否が変わった場合も確認を取消します。

### 起動時の復元

メインプロセスが保存済みの active 競技を復元し、ない場合だけ保存した競技種別で開始します。画面は2秒以上の起動画面と復元完了を待ち、既存の競技・着弾・得点照会から表示を復元します。照会前に通知を購読し、処理中に競技・セッションが変われば再照会します。着弾は ID で統合し、保存設定の種目で復元結果を上書きしません。

タイマーの所有サービスが開始時に競技 ID、絶対終了時刻、総時間、ステージ時計の位置を保存し、停止時に削除します。毎秒の書き込みは行いません。実行可否は競技状態が決め、古い時計キーは破棄します。単独使用では元の期限で再開し、期限超過なら通常の満了処理を行います。実行中の単独時計に期限がない場合はエラーとし、保存した競技の終了を案内します。

Director 参加中の通常時計は、射撃や次シリーズの開始が可能な待機中も PAUSED にします。最終シリーズ完了後は Lane が作った再起動停止だけを解除し、新しい停止案件を作らず Director の時間満了・終了を待ちます。公式の停止案件は保持し、同じ案件から再開できます。時計が動かず停止案件もない場合は、時計欄に「Waiting for Director」を表示します。実行中だった中断は Lane 発行の UUID を持つ再起動停止になり、Director の新しい停止案件が採用するまで再開を拒否します。既存の PAUSED / RESUME_PENDING は同じ案件の PAUSED に戻します。期限がない場合の保存残り時間は未検証としてログと Lane の停止画面に表示します。役員は Lane 画面の「Remaining time not verified — check the time before resuming」を確認し、許可時間を決めます。安全停止・射座移動は既存の所有処理に従い、標的時間制御の実行中シリーズはこの通常時計の停止対象にしません。25m の RESUME_PENDING は同じ案件の PAUSED に戻し、保存した再開予定時刻では自動再開しません。

復元できない競技設定、欠けた競技・セッション、所有記録の矛盾、参加先と active 競技の不一致も復旧画面に表示します。参加状態がなくなった停止済み競技は自動・ローカル操作では再開せず、確認付きの Finish saved run で着弾を保持して終了できます。参加中や安全停止中は終了できません。MQTT の手動接続は復旧画面からも利用できます。ERROR では時計と標的データの取り込みを動かさず、競技状態・得点は再発行しません。Director の競技別コマンドと join は復元未完了を示す error ACK で拒否します。leave、安全 STOP の操作、時計照会は利用でき、保存済み資料の outbox 配送は継続します。読めない保存競技には、参加状態がなく、安全 STOP と保留中の予備射座移動もない場合に限り、確認付きの Set aside saved run を用意します。active 参照だけを外します。未知の保存種別は代替種別で自動開始せず、復旧画面から有効な種別を選んで作成します。READY での Retry は現在状態の照会だけで、自動接続や復元を再実行しません。

### タイマー

- ステージ全体のタイマーは、同じステージのシリーズ間でも継続する。
- シリーズのタイマーは、次のシリーズで新しい持ち時間を使う。
- 決勝には1発ごとのタイマーもある。射数・時間は競技種別で決まる。
- 残り時間は分・秒と進行バーで表示する。残り60秒で黄色、30秒で赤色になる。
- Director 連携時は絶対開始時刻を基に計算する。再接続しても持ち時間は最初からには戻らない。

時計の検査条件と遅延時の処理は [MQTT 連携仕様](./MQTT_DESIGN.md#時刻とタイマー) を参照してください。

### 安全停止と中断

| 状態                 | Lane の動作                                          | 解除・再開                                              |
| -------------------- | ---------------------------------------------------- | ------------------------------------------------------- |
| STOP                 | 中断時の残り時間を保存し、タイマーを停止             | 許可内容を記録した Director から再開                    |
| STOP / UNLOAD        | 開始操作を禁止し、以後の射撃データを通常採点から隔離 | Director で安全確認を記録して解除。タイマーは再開しない |
| SIGHTING（中断復旧） | 許可された追加試射を記録                             | Director の「Resume MATCH fire」で本射へ戻る            |

証拠保全中や未完了の中断記録がある場合、記録のリセット・競技離脱・保持データの消去は拒否されます。解除条件は [中断と安全 STOP](../director/OPERATIONS.md#中断と安全-stop) を参照してください。

## 着弾・得点・表示

標的の着弾座標は中心を原点とする mm 単位です。得点は0.0〜10.9の範囲を使用します。装置が報告した得点、座標から計算した得点、実際に採用した得点を区別します。採用条件は機器と競技種別に従います。標的面、採点ゲージ、インナー10の判定は [標的・採点データ](../common/TARGET_SPEC.md) にまとめています。

| 表示                 | 対象・精度                                       |
| -------------------- | ------------------------------------------------ |
| 標的上の着弾         | 直近8発。番号を表示し、最新弾を得点別に色分け    |
| 最新弾の色           | 10点は赤、9点は黄、8点以下は青。過去の着弾は灰色 |
| 左側の着弾一覧       | 直近10発の番号と得点                             |
| 合計点・シリーズ得点 | RING は整数、DECIMAL は小数1桁                   |
| シリーズ得点の配置   | 2行×3列の表示領域。超過分は行単位で縦スクロール  |
| 平均点               | 小数2桁                                          |
| ズーム               | 自動、8点圏、6点圏、4点圏、標的全体の5種類       |

自動ズームは直近8発が収まる倍率に調整します。表示件数から外れた着弾も、保存済みの記録には残ります。着弾音は受信データを着弾へ変換できたとき、1 発につき 1 回鳴ります。音が鳴ったことだけでは、採点対象として記録されたことを確認できません。画面の得点、シリーズ内の射数、必要に応じてログも確認してください。

キーボード操作は [Lane 操作ガイド](./README.md#表示を調整する) を参照してください。入力欄の編集中はテンキーの操作ショートカットは働きません。

## 記録と出力

セッションは着弾の記録単位で、本射への移行や競技のやり直しで切り替わります。試射の着弾を本射の合計点へ加算しません。25m 決勝のヒット数集計では、元の得点も保持します。

| 出力先          | 内容・制約                                                   |
| --------------- | ------------------------------------------------------------ |
| Lane の印刷画面 | 現在のセッション。本射があれば本射のみ、なければ現在の全着弾 |
| MQTT            | 接続・進行・割当・得点の最新状態と着弾イベント               |
| ローカルデータ  | 設定、セッション、着弾、進行状態などを保存                   |

過去のセッションを選んで開く履歴画面はありません。個票の項目、得点単位、改ページは [帳票仕様](../common/PRINT_SPEC.md) を参照してください。「Printing」で出力先を保存すると直接印刷します。未設定時、または「Preview」を選んだ場合は印刷画面と OS の印刷ダイアログを使います。PDF 保存はプレビュー方式で利用できます。専用の履歴一括エクスポート操作ではありません。

## データの保存場所

「Settings」→「JSON」に表示される設定ファイルのパスを確認してください。既定のユーザーデータフォルダーは次のとおりです。

| OS      | パス                                        |
| ------- | ------------------------------------------- |
| Windows | `%APPDATA%\Saika Lane\`                     |
| macOS   | `~/Library/Application Support/Saika Lane/` |
| Linux   | `~/.config/Saika Lane/`                     |

| ファイル          | 保存内容                                |
| ----------------- | --------------------------------------- |
| `settings.json`   | 接続、ユーザー設定、MQTT 設定、印刷設定 |
| `saika-lane.db`   | セッション、着弾、得点など              |
| `saika-lane.json` | 互換設定、接続履歴、進行中の競技状態    |

設定ファイルだけでは記録をバックアップできません。アプリを閉じてフォルダー全体をコピーします。手順は [設定と記録の保存](./README.md#設定と記録を保存する) を参照してください。複数端末に同じ設定を複製すると Lane ID も重複し得るため、端末ごとに設定します。
