# 公開コンテンツ方針

Saika Docs に追加する内容は、次の条件を満たす必要があります。

- 投稿者自身が作成し、MIT License で提供する権限を持つこと。
- 第三者資料を利用する場合は、互換性のあるライセンスと必要な表示をファイル単位で記録すること。
- 競技規則、製品マニュアル、論文などは原文を収録せず、一次情報へのリンクと独自の要約を使うこと。
- 第三者のソースコード、抽出済みコード、バイナリ、画像、画面、帳票テンプレートを持ち込まないこと。
- パケットキャプチャ、復号情報、非公開 API、アクセス制御を回避して得た情報を持ち込まないこと。
- 相互運用文書は、公開済みの自作実装と公式一次情報を根拠にし、「Saika が受理する形式」と
  「メーカーの公式仕様」を明確に区別すること。
- 未確認のコマンド、チェックサム、電気特性、動作保証を推測で補わないこと。
- 契約、秘密保持義務、雇用上の職務著作、営業秘密に抵触しないことを投稿者が確認すること。
- 個人情報、認証情報、実在選手の記録、機器固有 ID を削除または匿名化すること。
- 商標は対象の識別に必要な範囲でのみ使用し、提携や公式性を示唆しないこと。

出典または権利関係が不明な内容は、確認が完了するまでこのパッケージに追加しません。

## マニュアルと外部仕様の書き方

- 日本語と英単語の間に半角スペースを入れる。
- 操作ごとに、前提、入力、操作後の状態・出力、失敗時の対応を説明する。
- 同じ仕様は一箇所にまとめ、操作ガイドから詳細へリンクする。単純な操作に不要な項目を増やさない。
- 操作ガイドは作業順に書く。詳しい設定値やデータ形式は仕様資料にまとめ、手順の途中から参照できるようにする。
- 例は入力形式や操作結果の理解に必要な分だけ示す。作業ログ、内部の改善件数、根拠のない評価語は操作説明に含めない。
- ページ冒頭が案内リンクの場合は、front matter の `description` に内容の要約を1文で記載する。文書カタログや共有時の説明に使われるため、本文の更新に合わせて要約も見直す。
- 実装済みの動作、実機での検証状態、未対応の範囲を区別する。性能目標を保証値として記載しない。
- 内部クラス、依存関係、実装手順は開発資料に置く。外部連携に必要なデータ形式・単位・制約は本文に残す。
- 画面名やボタン名は実際の表記を使用し、変更時はリンクと操作後の結果も確認する。
