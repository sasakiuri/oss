## 結果を確認して公表する

大会の種目を選び、「Results」を開きます。予選の成績行と公表パネルは別の状態を表示します。

- 成績行の「Published」：大会へ保存され、確認対象になった成績。公式公表済みという意味ではない。
- 成績行の「Confirmed」：「Confirm」で確定した成績。RTS 承認と公式公表は別途必要。
- 「Publication」：暫定掲示、抗議受付、公式公表の状態を確認する場所。

予選では次の順に確認します。

1. 「Results」で対象の射群または「All」を選び、成績を確認して「Confirm (件数)」で確定する。
2. 「RTS verification」で [成績の照合と承認](#rts-照合と承認を記録する) を行う。承認はその時点の成績一覧に対応する。
3. 暫定結果を実際に掲示した後、「Publication」に担当者、掲示先、掲示時刻を入力し、「Record preliminary posting」を押す。
4. 「Score protest ends」で受付期限を確認する。受付期間は実際の掲示時刻から始まる。得点への抗議は「Score protests」で参照番号を入力して「Register」を押す。裁定後は「Resolve」を開き、担当者と裁定内容を入力して「Append resolution」で記録する。
5. 「Official publication blockers」を確認し、必要な確認・承認・抗議処理を完了する。受付期間の終了後、「Publish official results」を押し、状態を確認する。

暫定掲示後に成績が変わった場合は、現在の一覧を掲示し直して「Record revised posting」で記録します。公式公表後に要再確認の表示が出た場合は、大会の訂正手順に従ってください。過去の公表履歴は残ります。

決勝は「Results final」を開きます。順位、RTS 承認、即時抗議の裁定、氏名・国名などを確認し、「Declare RESULTS ARE FINAL」で宣言を記録します。予選の暫定掲示・受付期間とは別の手順です。

抗議の受付詳細、書面・上訴、裁定履歴は [抗議・上訴台帳](#抗議上訴の受付と裁定を記録する) で管理します。

追加の公表条件で事故報告や用具検査が未完了と表示された場合は、[事故報告](#事故報告を記録する)・[用具検査](#競技後の用具検査を記録する) の記録を確認します。銃器故障の未完了案件も予選成績の公表を止めます。競技終了前の記録と画面の制約は [予選の銃器故障](./OPERATIONS.md#予選の銃器故障を記録する) を参照してください。

### RTS 照合と承認を記録する

予選・決勝とも、種目の「Results」→「RTS verification」を開きます。表示された対象成績を、標的の印刷物や独立した記憶元の記録と照合します。

1. 対象選手の「Review」を押し、「Independent source」で資料の種類を選ぶ。「Source reference / printout ID」に、その資料を特定できる参照番号を入力する。
2. 「Score comparison」で一致、不一致、比較不能の結果を選ぶ。手動修正がある場合は内容を確認し、「Reviewed all … manual intervention(s)」にチェックを付ける。
3. 「RTS Jury member」に確認者を入力し、「Append verification check」で記録する。対象を順に確認し、「Required individual checks」の件数と「Approval requirements」を確認する。
4. 必須の確認が完了したら、「Approving RTS Jury member」と「Accuracy statement」に承認者と確認内容を入力する。下記の署名方法を選んで「Approve this result-list revision」を押し、「RTS Jury approval」が「Current」になったことを確認する。

「Other evidence (audit only)」、不一致、比較不能は確認記録として保存されますが、承認に必要な一致確認にはなりません。資料や得点を確認・修正してから照合し直します。成績変更で「Stale」になった場合も再照合が必要です。団体の照合が必要な場合は、[EST backup](#独立バックアップを保存印刷照合する) で現在の団体成績を照合します。

「Signature method」で承認の記録方法を選びます。

- 「Personal signature / manual confirmation」：サインイン中は本人署名となり、「RTS Jury (result approval)」の役割が必要。[担当者の登録](./OPERATIONS.md#担当者の登録とサインイン) で確認する。未サインインなら手動確認として記録する。
- 「Record an external signature」：外部で取得した署名を記録する。署名済み資料の参照を入力し、未サインインなら記録者も入力する。

サインインが必須の運用では、どちらの方法も先にサインインします。

### 種目ごとの公表条件を設定する

追加の確認を公表条件にする場合は、承認前に「RTS verification」→「Event review settings」を開きます。

1. 「Settings source」で設定元を選ぶ。「Follow shared defaults」は全体設定に従い、「Fixed for this event and round」は種目・ラウンドごとに固定する。
2. 固定する場合は、着弾資料、事故報告、用具検査、抗議台帳、決勝の復旧など、必須にする確認を選ぶ。
3. 「Responsible official」と「Reason for these event settings」に担当者と理由を入力し、「Save event settings」で保存する。設定と「Event setting history」を確認する。

固定した項目は [Director 全体の運用設定](./OPERATIONS.md#開始前の運用設定) を変えても追従しません。サインイン中の変更には RTS Jury の役割が必要です。設定や全体の既定値が他の操作で変わった場合は、「Reload event settings」で読み直してから保存します。

保存後は成績一覧の再承認が必要で、暫定掲示済みなら改訂版の掲示も記録します。この設定の変更だけなら、個々の照合記録は維持されます。公式公表・決勝の最終宣言後は、この設定を変更できません。

### 抗議・上訴の受付と裁定を記録する

大会の種目にある「Protests and Appeals」を開きます。

1. 「Lodge」を押し、「Type」で口頭、書面、決勝の即時口頭、上訴の区分を選ぶ。上訴では「Parent protest」で元の抗議を指定する。
2. 件名、内容、申立人、受付担当者と実際の受付日時を入力する。日時は PC のローカル時刻で入力し、納付額が未確認なら空欄にする。書面・上訴では判断の起点時刻と様式の参照番号も記録する。
3. 「Record」で保存し、受付情報の不足や期限に関する表示を確認する。保存できたことだけでは、受理条件を満たしたことにはならない。
4. 対象記録の「Action」で Jury への付託や裁定を選び、担当者、実際の日時、内容、規則の参照を入力して「Append action」を押す。認容は `DECIDED_UPHELD`、一部認容は `DECIDED_PARTLY_UPHELD`、棄却は `DECIDED_REJECTED` を選ぶ。
5. 裁定後に必要な納付金の処理を記録し、確認が完了したら「CLOSED」を追記する。履歴と状態を確認する。

裁定は1件につき1回だけ記録できます。「CLOSED」後は追記できません。裁定の記録前と案件を閉じる前に、対象と内容を確認してください。

台帳の裁定で得点は自動修正されません。変更が必要なら [得点修正](#資料に基づいて得点を修正する) を行います。公式書類は記録の「Print operational copy」から [PDF の準備](#抗議上訴の公式-pdf-を準備する) へ進みます。

台帳と「Publication」の「Score protests」は別の記録です。両方に登録した案件はそれぞれに処理結果を記録します。「Complete protest cases」を必須にした運用では、裁定済みの `DECIDED` も公表を止めるため、台帳の確認を完了して閉じます。公表画面を開き直し、残る未完了項目を確認してください。

## 成績一覧を印刷する

大会の種目に成績を保存してから操作します。競技中の Lane の記録を印刷する場合は、[Lane の印刷手順](../lane/README.md#記録を印刷する) を使います。

1. 「Championships」で大会と種目を選び、「Results」を開く。予選では「Relay」で対象の射群、または全射群の「All」を選ぶ。
2. 「Print」を押し、別ウィンドウに表示された種目・射群・選手・得点を確認する。予選では公表状態と抗議受付期限も確認する。
3. 印刷画面の「Print」を押し、OS の印刷ダイアログで出力先を選ぶ。PDF 保存が選べる環境では、ファイルとして保存できる。
4. 用紙と改ページを確認して出力し、「Close」で印刷画面を閉じる。

成績や公表状態を変更した場合は、印刷画面を開き直します。印刷だけでは成績の確定・承認・公表は行われません。

個人決勝も「Results」の「Print」から出力します。混合団体決勝の成績表には、この印刷ボタンはありません。決勝帳票の発数構成などの制約は [帳票仕様](../common/PRINT_SPEC.md#director-の決勝成績一覧)、大会全体の出力は [成績冊子の保存](#成績冊子と証拠資料を保存する) を参照してください。

| 困ったとき                         | 確認すること                                                                                                    |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 「No results」や「No result data」 | 大会・種目・射群を確認し、[競技終了時の成績保存](./README.md#4-終了して成績を確認する) が完了したか調べる       |
| 印刷画面を開けない                 | エラーを確認する。元の「Results」で成績を読み込めることを確認してから、再度「Print」を押す                      |
| 得点や順位が想定と異なる           | 対象選手、参加区分、裁定履歴を確認する。得点修正は [資料に基づく修正手順](#資料に基づいて得点を修正する) を使う |

## 団体成績を確認する

予選の団体成績は、参加者の「Team ID」でまとめた個人成績から計算します。所属が同じでも、団体 ID が未入力なら集計されません。登録方法は [参加者の入力](./README.md#参加者の入力と貼り付け) を参照してください。

1. 種目の「Results」→「Team results」を開く。
2. 集計形式の選択欄で「3-member Team」または「Mixed Team pair」を選ぶ。
3. 「Members」、「Total」、「Checks」で構成員、合計点、確認事項を読む。登録や個人成績を修正した場合は「Refresh」で再計算する。

Saika は次の構成条件を検査します。

- 「3-member Team」：3人で、登録された性別が同じ。性別の未指定は不可。
- 「Mixed Team pair」：2人で、登録上の性別が `M` と `F` の1人ずつ。
- 共通：全員が `COMPETING` で同じ国コードを持ち、順位付けできる個人成績がある。入力した団体名も揃える。

「Eligible」は構成と成績の条件を満たした状態です。承認・公式公表済みという意味ではありません。不足があれば「Checks」の内容に従って参加者情報と個人成績を確認します。

「Unresolved tie — same rank」や Jury の確認を求める表示がある場合は、同点処理の根拠を権限者が確認してください。

混合団体決勝では「Results」に団体別の成績を表示します。各選手の得点と、[決勝進行](./OPERATIONS.md#決勝の進行) で記録した順位を確認します。

## 資料に基づいて得点を修正する

個人成績の行にある天秤ボタンを押すと、「Scoring decisions — 選手名」が開きます。対象の選手と元得点「Source score」を確認します。裁定反映後の得点は「Projected score」に表示されます。

減点やミスなどの裁定は「Append official decision」で種類と対象を選び、規則の参照、公開備考、担当者を入力して「Append decision」で記録します。記録後は「Decision history」と反映後の成績を確認してください。

誤った裁定は「Revoke」で対象を選び、担当者・規則の参照・撤回理由を入力して「Append revocation」で撤回します。

着弾の得点や射順を修正する場合は、裁定済みの調査資料を関連付け、次の順で操作します。

1. 「Restore or correct shots from Jury evidence」を開き、担当者、確認内容、「Linked Jury evidence」を入力する。資料の候補がなければ、[標的調査の手順](./OPERATIONS.md#調査資料を残す) で大会・競技との関連付けと Jury の判断を確認する。
2. 「Action」で置換または欠落射の挿入を選び、「Shot number」に1始まりの射順を入力する。修正点と「Evidence / IR reference」を入力する。
3. 「Preview corrected result」で変更される全射と、減点前の合計を確認する。
4. 選手、資料、変更位置を確認してチェックを付け、「Apply confirmed correction」を押す。
5. 履歴の「Active」、修正後の成績、再確認が必要な項目を確認する。

得点は点単位で入力します。整数点は0〜10、小数点は0.0〜10.9、ヒット採点は1または0です。欠落射の挿入は以後の射順をずらし、末尾の1発を集計から外します。元の着弾記録は変更しません。

プレビュー後に入力や根拠が変わった場合は、再度プレビューしてください。修正を撤回する場合は担当者と理由を入力し、「Withdraw correction using the official and reason above」を使います。適用・撤回後は RTS 承認、公表状態、決勝の順位再確認を見直します。

## 事故報告を記録する

大会の種目で「Incidents」→「Range Incident Reports」を開きます。中断・故障・裁定の根拠を記録する台帳です。

1. 「New incident report」を押す。「IR serial number」に種目内で重複しない報告番号を入力する。
2. 発生日時、射群・射座、対象選手、事実、規則の参照、作成担当者と役割を入力し、「Create report」で保存する。
3. 対象報告の「Append audit entry」で「Add official sign-off」を選び、役割と担当者を入力して「Append entry」で確認を記録する。「Sign-off coverage」で記録済みの役割を確認する。
4. 「Print operational copy」で報告を開き、内容を確認して出力する。実際に写しを届けた後、「Record copy forwarding」で宛先と担当者を入力して「Append entry」を押す。「Forwarded」を確認する。

裁定と対応付けるには、[得点修正](#資料に基づいて得点を修正する) の「Incident report #」に同じ報告番号を指定します。「Decisions needing an active registered IR」が残る場合は、参照番号の未入力、未登録、報告の無効化を確認してください。報告の登録だけでは得点を変更しません。

元の事実は保存後に編集できません。補足は「Add audit note」で追記します。元の事実が誤っている場合は、担当者と理由を入力して「Void report」→「Append void entry」で無効にし、別の報告番号で作成し直します。無効化は取り消せないため、実行前に対象を確認し、関連する裁定の参照も見直してください。

## 競技後の用具検査を記録する

大会の種目で「Equipment Control」を開きます。対象者への通知や用具の検査は現場で実施し、その結果を次の順で記録します。

1. 「Select athletes for testing」で選定の根拠、担当者、確認内容と対象選手を指定し、「Record selection」で保存する。選手は手動で選び、抽選方式を選んだだけでは抽選されない。
2. 対象選手の「Record written notice」で、実際の通知方法、通知の参照番号、担当者と内容を記録する。
3. 「Outcome」で結果を選び、検査項目、実施者、監督する Jury、確認内容を入力して「Record test result」を押す。「Did not report」は通知の記録後に選べる。
4. 不合格・不参集の場合は「Confirm failed test / non-report」を開く。校正資料の参照、確認する Jury の氏名・役割・確認内容を入力し、「Confirm test and procedure」で記録する。
5. 状態と「Audit history」を確認する。「Separate disqualification action required」が出たら「Copy reference」で根拠の参照を控え、次節の失格判定を別途記録する。

用具検査の記録だけでは成績に失格を反映しません。検査を必須にした公表条件では、検査や判定が未完了の間は公表できません。保存できない場合はエラーに従い、検査項目、通知、確認者の役割を見直します。衣服・テーピングの検査では、画面に表示される同性審判員の確認も必要です。

## 失格判定と撤回を記録する

権限者の判断に基づく失格は、大会詳細の「Championship athlete identity and sanctions」で記録します。先に参加者を登録し、対象者と影響する種目を確認してください。

1. 「Recording official」と「Identity-link statement」に担当者と本人確認の根拠を入力する。「Reconcile ISSF IDs」で登録 ID を照合する。ID のない選手は「Manual identity」で氏名と該当する種目の登録を選び、「Create identity」で保存する。
2. 対象者に関連付いた種目・参加者を確認し、「Record sanction」を開く。
3. 「Classification」と「Source event」で区分と対象種目を選び、担当者、判断資料の参照、規則の参照、公開備考を入力する。用具検査に基づく DSQ は「Authority basis」で「Post-competition equipment check」を選ぶ。「Authority reference」に控えた参照を入力する。
4. 対象範囲を再確認して「Record DSQ」などの区分に応じたボタンを押す。「Active sanctions」と各種目の成績を確認する。

`DSQ` は指定種目の全ラウンド、`DQB`・`AD-DSQ` は大会内でその選手に関連付けた全種目へ反映します。氏名が同じという理由だけで別人の登録を関連付けないでください。

撤回は「Active sanctions」の対象で「Revoke」を押し、担当者、判断資料・規則の参照、公開する撤回理由を入力して「Confirm revocation」で記録します。元の得点と判断履歴は残ります。適用・撤回後は成績、公表状態、RTS 承認を再確認してください。

## 独立バックアップを保存・印刷・照合する

ここでの独立バックアップは、成績と照合するための別の記憶元から得た射撃記録です。Director 自体を復元する手順は [バックアップと復元](#director-のバックアップと復元) を参照してください。

種目の「Results」→「EST backup」（画面によっては「EST backup verification」）を開きます。原資料の保存・印刷に、成績照合や確定は不要です。

1. [取込形式](./EST_BACKUP.md) に合わせて資料の形式を選び、「Import JSON / CSV」または「Import delimited file」で取り込む。任意列の CSV／TSV は列名と区切り文字を指定する。
2. 「Retained source files」にファイル名と件数が表示されたことを確認する。原文、読み取った全レコード、列の対応が保存され、元ファイルの移動後や再起動後も利用できる。
3. 「Print source」を開き、必要なら「Include original source text」を選んで印刷する。
4. 照合する場合は「Use source records」で資料を読み込み、「Result kind」と「Comparison key」を合わせる。比較内容と担当者を入力し、「Compare and retain」を実行する。
5. 差異や未確認項目を調べる。保存・照合の成功だけでは RTS 承認や公式公表にはなりません。

原資料の読み出し時は整合性が検査されます。取り込んだ数値を編集すると元資料との関連付けが解除され、手入力資料として扱われます。機器・記憶媒体が主 EST コンピューターから独立していることは、実構成で確認してください。保存資料は大会の証拠エクスポートと DB バックアップにも含まれます。

照合キー、射順・シリーズ順の明細、比較結果の意味は [独立バックアップの取込形式](./EST_BACKUP.md) にまとめています。

### 更新される原資料を自動取得する

独立した記憶元がファイルを定期的に更新する場合は、同じ「EST backup」内の「Continuous backup capture」を使います。読取先は種目ごとに保存されます。

1. 「File layout」と、必要な場合は列の対応を [取込形式](./EST_BACKUP.md) に合わせる。
2. 「Check interval (seconds)」に確認間隔を1〜300秒の整数で入力する。既定は5秒である。
3. 「Snapshot mode」を選ぶ。「Two identical reads」は同じ内容を2回続けて読めた場合に保存する。「Complete files」は読めた内容を毎回検査するため、書出し側が完成したファイルへ一括で置き換える場合だけ選ぶ。
4. 再起動後も取得を続けるなら「Resume automatically after restarting Director」にチェックを付ける。「Choose source and start capture」でファイルを選ぶ。
5. `READY` と「Last retained」、および「Retained source files」に保存資料があることを確認する。印刷・照合にはその資料を使う。

- `WAITING`：保存条件を満たす読み取りを待っている。「Two identical reads」では次の確認を待つか「Check source now」を使う。
- `ERROR`：表示された原因を確認し、ファイルの場所・読取権限・入力形式を直す。取得中なら次の定期確認で再試行する。
- 「Stop capture」：自動取得を停止する。再起動後の自動再開も止まる。「Resume saved source」で保存済み設定から再開する。
- 「Forget saved source」：停止後に読取先の設定を削除する。すでに保存した原資料は残る。

同じ内容の再確認では資料を重複保存しないため、「Last retained」が変わらない場合もあります。ファイルの移動や読取条件の変更は、設定を確認してファイルを選び直します。自動取得だけでは成績を照合・確定・公表できません。すべての着弾の収録や記憶元の独立性も別に確認します。開始条件として使う場合は [自動取得の開始前検査](./OPERATIONS.md#独立バックアップの自動取得を開始条件にする) を設定します。

## 成績冊子と証拠資料を保存する

保存する目的に応じて出力を選びます。

| 目的                                                | 開く場所                                    |
| --------------------------------------------------- | ------------------------------------------- |
| 確認・認証した成績冊子を配布する                    | 大会の「Official Results Book and records」 |
| 大会の成績、裁定、調査資料などを保存する            | 大会詳細の「Export evidence」               |
| Director のデータベース全体を復元できる形で保存する | 「Settings」→「Operational archives」       |

成績冊子を作る前に、必要な結果公表と役員の登録を済ませます。「Championship official appointments」で「Role」、氏名、記録者、任命の根拠を入力し、「Record appointment」で登録します。本人がサインインして署名する場合は「Signing account (optional)」でその人のアカウントを関連付けてください。認証が必須の運用では、役員登録に管理者権限が必要です。

登録後は次の順で作成します。

1. 「Generate, certify and export Results Book」で作成者を入力し、「Generate book version」を押す。
2. 表示された未完了項目を確認する。元の成績や登録情報を修正した場合は、新しい版を作成する。
3. 「Signer statement」を入力し、必要な署名を「Sign」または「Record signature」で記録する。「Personal signature」は関連付けた本人がサインインして実行する。外部で取得した署名を記録する場合は「Record an external signature」を選び、記録者と署名済み資料の参照を入力する。
4. 確認者と確認文を入力して「Certify」を押し、`CERTIFIED` を確認する。
5. 「Export HTML」、「Export PDF」、「Export JSON」から選んで保存し、出力した版と内容を確認する。

サインインを必須にしない運用で、未サインインのまま「Personal signature」を使うと手動確認として記録されます。外部署名も本人のサインインとは区別して保存されます。

証拠資料は大会詳細の「Export evidence」で JSON ファイルへ保存します。出力完了の通知とファイルを確認し、対象大会・保存日が分かる形で保管してください。証拠資料の JSON は、[データベース復元](#director-のバックアップと復元) には使用できません。

## Director のバックアップと復元

「Settings」→「Operational archives」を開きます。更新前や大会の登録・結果確認後など、残したい状態でバックアップを作成してください。

### バックアップを作る

1. 「Create verified backup」を押し、保存先を選ぶ。
2. 「Verified database backup created」の通知と `.db` ファイルを確認する。
3. 保存したファイルを、運営用 PC の故障時にも取り出せる場所へ保管する。

バックアップ時にデータベースの整合性を検査します。大会・成績・取込済み資料に加え、データベースに保存された設定と担当者アカウントも対象です。各 Lane のローカルデータと外部ブローカーの保存内容は含みません。

### バックアップから復元する

復元は現在のデータベース全体を置き換えます。進行中の競技では行わず、現在の状態も先にバックアップしてください。

1. 「Inspect restore candidate」でバックアップの `.db` ファイルを選ぶ。
2. ファイル名、大会数、互換性の検査結果を確認する。エラーがあれば、表示された原因を解消する。
3. 再起動後に置き換わることを確認してチェックを付け、「Stage restore」を押す。
4. 「Restore pending for the next Director restart」を確認し、Director を再起動する。
5. 大会・種目・成績と接続設定を確認する。認証が必須なら、バックアップ時点のアカウントとパスワードでサインインする。競技の再開前には各 Lane の実際の状態も確認してください。

再起動前なら「Cancel pending restore」で取り消せます。適用時には置き換え前のデータベースも復旧用コピーとして保存されます。新しい版で作成したデータベースなど、互換性のないファイルは復元できません。

## 抗議・上訴の公式 PDF を準備する

1. 種目の「Protests and Appeals」で記録を選び、「Print operational copy」を開く。
2. 書面抗議・上訴では「Transfer values to a protest or appeal form」を開き、タイムゾーンを指定する。初期値は UTC、日本では `Asia/Tokyo` を使える。
3. 各項目を確認し、必要な種目名・Jury 名・国名・受付担当者を補う。受付日時は実際の受付記録を使い、未記録の時刻や納付額は手動で確認する。
4. 「Complete official PDF and check submission materials」で不足欄を補い、公式原本を選ぶ。対応原本は Form P／AP の`Edition 2025 (Second Print 07/2026)` である。
5. 「Check completion through」で提出・受領・裁定と通知の確認段階を選び、実際の書類の署名と添付資料を確認する。
6. 「Export draft official PDF」で下書きを保存し、両ページを確認して必要な署名をする。日本語などには、その文字を収録した TTF／OTF フォントを指定できる。

この補足入力は一時的で、台帳・裁定・結果承認を変更しません。入力の変更で署名・添付のチェックは未確認に戻り、画面の再読込で補足入力は消えます。

一部認容の二択への転記、会議・通知時刻、署名などは人が確認して完成させます。文章が欄に収まらない場合は、短くして添付資料を参照してください。

原本は変更されず、PDF の署名欄は空欄のままです。未完了でも下書きは出力できますが、出力だけで署名・提出・受領は行われません。添付資料は別途用意します。上訴には元の公式抗議様式を添付し、Director の運用記録の印刷物で代用しないでください。
