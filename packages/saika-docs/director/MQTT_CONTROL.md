# Director MQTT 制御・運用

[Director 操作ガイド](./README.md)

競技参加、選手割当、成績保存、再試行の条件を説明します。トピックとデータ形式は [MQTT 連携仕様](../lane/MQTT_DESIGN.md) を参照してください。

## 接続構成

内蔵ブローカーは既定で `mqtt://localhost:1883` を使います。別 PC の Lane からは、Director の設定画面に表示する IPv4アドレスとポートを使用します。外部ブローカーを選ぶ場合は、Director と全 Lane の接続先を揃えます。

接続設定は、接続先の切り替えが成功した後に保存します。失敗した場合は、直前の設定と接続へ戻します。複数の変更操作は受け付けた順に処理します。

内蔵ブローカーの認証と、Lane でのコマンド認可は独立した設定です。必須の認証情報が不足する構成や不正な値は、弱い設定へ変更せず起動時に拒否します。具体的な設定は [MQTT セキュリティ設定](../../saika-director/README.md#mqtt-security-configuration) を参照してください。

## 競技参加

競技作成と参加指示は次の順に処理します。

1. 対象 Lane を含む暫定の競技状態を Retain 付きで発行する。
2. 各 Lane へ `join-competition` を送る。
3. Lane が競技状態とローカルの競技定義を照合する。
4. `done` ACK を返した Lane の参加を確定する。

Rule Pack を使う競技では、ID、スキーマ版、内容の SHA-256を両アプリで確認します。互換性の確認が `REQUIRED` の場合、不一致の Lane は参加できません。ビーム競技などのローカル定義には、設定に応じた警告・無効の扱いがあります。

| 結果                  | Director の状態と次の操作                                            |
| --------------------- | -------------------------------------------------------------------- |
| done                  | 参加確定。選手割当へ進む                                             |
| error                 | 対象 Lane を競技状態から除外。原因を解消して参加を再試行             |
| timeout・送信結果不明 | 対象を参加待ちとして保持。試射開始を禁止し、同じ競技への参加を再試行 |

タイムアウト時は、Lane で参加が保存され、応答だけ失われた可能性があります。再試行すると、参加済みの Lane も同じ競技を確認して `done` を返します。不要な Lane は離脱して保留を解消します。

通常の参加・離脱は `NOT_STARTED` の間だけ可能です。試射開始が一部だけ成功した場合は、`pendingSightingLaneIds` に残る未開始の Lane に限り離脱できます。

## 大会管理の射座割

「Competition Control」→「Championship assignment」で、大会・種目・射群を選んで「Apply assignments」を押します。保存した射座番号が一致する参加済み Lane へ選手を設定します。

### 射座番号と選手の対応

Director は「Lane Alias」に含まれる最初の連続した数字を読み、値が `1`〜`99` なら射座番号に優先して使います。例えば `Lane 12` は `12` です。数字がない、範囲外、または他の Lane が同じ番号を指定している場合は、空いている番号を設定します。Lane の「General」の射座番号は、この対応付けには使いません。

競技開始前に「Lanes」一覧の番号を確認してください。`offline` の Lane は番号を保持しないため、同じ Alias の交換機がその番号を使用できます。Alias を変更すると対応付けも更新されるため、変更後は選手の射座割を再確認します。

選手 ID は大会の参加者 ID、制御用のスタート番号は参加者一覧の1始まりの順番です。公式登録のスタート番号とは区別します。団体 ID・団体名・性別・国コード・ISSF ID は独立した項目で、所属文字列から団体を推測しません。

### 反映と変更の制約

| 条件                             | 動作                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| 大会種目と競技の種別が不一致     | 反映を拒否                                                     |
| 対応する Lane または参加者がない | その射座割を送信せず、未対応として表示                         |
| 一部 Lane への割当が失敗         | Lane ごとの結果を表示。失敗原因を解消して再試行                |
| 大会連携中に手動で選手を補正     | 番号と氏名を参加者一覧で照合。一意に特定できなければ変更しない |
| 試射・本射中                     | 通常の選手割当変更を拒否                                       |
| 終了時に成績保存が失敗           | 保持データ消去の開始前に限り割当を補正できる                   |

### コンピューター抽選

手動の射座割とは別に、ISSF 用のコンピューター抽選を利用できます。操作は [コンピューター抽選の手順](./OPERATIONS.md#コンピューター抽選で射座を割り当てる) を参照してください。抽選条件、参加者の記録、配置結果を保存し、同じ国・団体の分散や混合団体の配置条件を検査します。

Technical Delegate の承認と明示確認後に、保存済み射座割を置き換えます。参加者一覧が変わった場合は再抽選が必要です。混合団体決勝の左右交替は、所定の通知を確認した後に手動の射座割へ反映します。

## コマンドの実行と再試行

応答の形式は [コマンドと応答](../lane/MQTT_DESIGN.md#コマンドと応答) を参照してください。Director は既定で10秒待ち、対象 Lane がすべて `done` を返した場合だけ操作全体を成功とします。

同じ競技への操作は受け付けた順に処理し、その時点の状態を再検査します。参加・離脱・終了時の所属変更は競技をまたいで調整し、同じ Lane を複数の競技へ確保しません。

一部の Lane だけ進行した場合、再試行は現在状態を確認して未完了の処理を進めます。成功済みの処理は自動的に取り消されません。射場全体の STOP も、全 Lane で同時に成功することを保証する操作ではありません。Lane ごとの応答と実際の状態を確認してください。

### 試射開始

一部の Lane で試射開始に失敗した場合、未開始の対象を `pendingSightingLaneIds` に保持します。全対象の開始を確認するまで試射終了は無効です。「Retry sighting for pending Lanes」は元の開始時刻を使い、再送時から持ち時間を延ばしません。

### 記録のリセット

`reset-session` の `done` は、Lane の着弾・得点の消去と、0点の保持スコアの発行が完了してから返します。Director も成功応答後にその Lane の旧着弾表示を破棄します。

完了応答だけ失われた場合、Director に古いイベントの表示が残る場合もあります。終了時の成績明細には最終の保持スコアを使います。調査資料の保全や中断中の制約を解消せず、リセットで復旧しようとしないでください。

## タイマーの開始と再試行

開始時刻は既定で送信の3秒後です。PC 間の時計同期が前提で、検査条件は [時刻とタイマー](../lane/MQTT_DESIGN.md#時刻とタイマー) にまとめています。

| 保持する値     | 用途                                           |
| -------------- | ---------------------------------------------- |
| `pendingTimer` | 配信前に保存した未確定操作の開始時刻・持ち時間 |
| `activeTimer`  | 成功応答後に確定したタイマー                   |
| 元の満了時刻   | 再接続後も同じ期限で満了を通知                 |

Lane の成功応答後に状態保存が失敗しても、再試行は最初の時刻と持ち時間を使います。新しい時間からやり直しません。タイマー再開の未確定中は、古い期限で Lane を終了させる通知を送らず、再試行の成功後に期限を切り替えます。

未確定の試射開始を受けた可能性がある Lane をすべて正常に離脱させた場合、その未確定タイマーを消去します。その後に交換 Lane を参加させる場合は新しい開始時刻を設定します。

## 25m・決勝・中断の制御

画面操作は [25m の標的時間制御](./OPERATIONS.md#25m-の標的時間制御)、[決勝の進行](./OPERATIONS.md#決勝の進行)、[中断と安全 STOP](./OPERATIONS.md#中断と安全-stop) を参照してください。

| 操作                   | 実行条件と結果                                                                   |
| ---------------------- | -------------------------------------------------------------------------------- |
| 25m のシリーズ開始     | Rule Pack のステージ・シリーズ・プログラムと、全対象の安全・時計・進行位置を確認 |
| 次の LOAD              | 前シリーズの終了と待機時間、必要な UNLOAD の記録を確認                           |
| 決勝の脱落             | 順位判断を記録してから対象 Lane へ送信。混合団体は両 Lane の成功で完了           |
| 中断からの再開         | 停止時の残り時間と、役員の許可内容を指定                                         |
| 25m 予選の再射・補射   | 中断記録の判断と対象シリーズを照合し、通常の本射と分離して記録                   |
| 復旧射の採点反映       | 射撃完了と証拠の一致後に明示適用。許可された未発射分はミスとして補完             |
| 記録済みシリーズの維持 | 追加射撃・再採点をせず、判断と既存記録を照合して完了                             |

安全 STOP や競技中断は、実行中の標的時間制御を取り消して赤の状態へ戻します。物理ランプ・標的回転装置への出力と音声 UNLOAD は、この制御には含みません。

判断の記録、射撃の実行、採点の適用は別操作です。再試行では保存済みの同じ実行単位と時刻を使います。銃器故障は [専用の記録・計算書](./OPERATIONS.md#予選の銃器故障を記録する) で扱い、中断による無効・再射の手続きで代用しないでください。

## 終了と成績保存

終了処理では、次の順に確認します。

1. Lane を終了し、最終の割当・得点を取得する。
2. 大会に連携した競技では、保存先と参加者・射群・採点方式を検証する。
3. 成績を保存し、消去前の処理完了を `cleanupPreparedAt` に記録する。
4. Lane を離脱させ、割当・得点・競技状態の Retain を消去する。

| 条件                                   | 保存・終了の扱い                                            |
| -------------------------------------- | ----------------------------------------------------------- |
| 本射開始前、または大会の射座割を未反映 | 大会成績を保存しない。終了前に保存先がない警告を表示        |
| 選手が保存先の射群に含まれない         | 成績保存を拒否。割当を補正して再試行                        |
| 得点の採点方式が競技種別と不一致       | 成績保存を拒否                                              |
| 再試行先に同一の確定成績がある         | 確定状態を維持して再利用                                    |
| 確定成績と得点・選手・対象範囲が異なる | 射群全体の置き換えを拒否                                    |
| 保存先の種目が削除されている           | 終了後の割当・得点を残す。同じ種別の保存先と射座割を再設定  |
| 資料保全・未完了の中断がある           | 記録の消去を保留。必要な資料確保と解除後に再試行            |
| 離脱・Retain 消去に失敗                | 完了済み処理を保持し、「Retry cleanup」で未完了部分を再試行 |

成績へ保存する氏名・所属は、大会データベースの参加者 ID に対応する値を使います。Lane 側の古い表示名だけで大会の正式情報を変更しません。

証拠保全中は、Lane を終了して最終状態を取得しても、離脱と Retain 消去は行いません。保存済みの成績を不必要に作り直さず、保留解除後に消去処理を再開します。

## Retain と復旧

内蔵ブローカーは Retain を Director のデータベースに保存し、再起動時に復元してから接続を受け付けます。外部ブローカーでは、プロセス再起動後の復元に永続化設定が必要です。

競技の参加 Lane、選手割当、得点、タイマー、中断・安全状態などを最新の保持データから復元します。着弾イベントは Retain しないため、最新状態の復元と全履歴の取得は別です。

Lane は60秒ごとにハードウェア状態を発行します。Director は最後の発行から150秒を超えた状態を `offline` と扱います。古い保持データだけで Lane を接続済みにせず、新しい報告で状態を更新します。

Director の再起動後は、元の期限から残り時間を計算します。満了済みなら同じ満了時刻を通知します。応答不足や状態保存の失敗がある場合も、完了を確認するまで期限を保持して通知を再試行します。

## 障害時の確認順序

1. Director のブローカー状態と接続 URL を確認する。
2. Lane の標的接続と MQTT 接続、競技 ID を確認する。
3. 直前の操作について、Lane ごとの ACK と現在の画面を確認する。
4. `error` はコードとメッセージの原因を解消する。
5. `timeout` は接続と実際の状態を確認してから再試行する。

コマンドを連打しても状態不一致は解消しません。大会中の判断と資料保全は [Director 運用ガイド](./OPERATIONS.md) に従ってください。
