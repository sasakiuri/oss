# 帳票仕様

Saika Lane と Saika Director が扱う印刷帳票の機能要件をまとめる。
この文書は、移植元の設計を Saika 独自の帳票仕様として書き直したものであり、競技団体や
標的装置メーカーが提供する公式帳票、帳票テンプレート、画面意匠の複製ではない。

競技会で使用する場合は、主催団体の現行規則、保存要件、署名要件と照合すること。

## 1. 対象と実装状況

| 帳票名           | 主な用途                        | 対象          | OSSでの状態          |
| ---------------- | ------------------------------- | ------------- | -------------------- |
| ScoreSheet       | 1射座・1セッションの得点明細    | Qualification | Saika Laneで実装済み |
| ResultsListSheet | 種目または射群の順位・得点一覧  | Qualification | Director向け設計資料 |
| FinalResultSheet | Finalの累積得点、脱落、同点決着 | Final         | Director向け設計資料 |

「Director向け設計資料」は、公開OSSに対応実装が含まれることを意味しない。Directorを公開する際は、
その時点の型、実装、テストを正として本書を再監査する。

ScoreSheet の公開実装:

- [データ生成](../../saika-lane/src/main/modules/report/application/handlers/GetScoreSheetHandler.ts)
- [表示コンポーネント](../../saika-lane/src/renderer/presentation/screens/print/components/ScoreSheet.tsx)
- [印刷用CSS](../../saika-lane/src/renderer/presentation/styles/print.css)
- [DTO](../../saika-lane/src/main/modules/report/application/dto/index.ts)

## 2. 共通仕様

### 2.1 出力フロー

1. 呼び出し元が帳票種別と対象IDを指定する。
2. アプリケーション層が印刷専用DTOを生成する。
3. 印刷ウィンドウにHTMLとして描画する。
4. 画面上の操作部を印刷時に非表示にする。
5. OSまたはブラウザーの印刷機能で出力する。

### 2.2 ページと表示

- 基準用紙はA4縦、印刷余白は10mmとする。
- 帳票または選手の境界で改ページし、行やシリーズの途中では可能な限り分割しない。
- 文字は可読性の高いsans-serif、数値は桁を比較しやすい配置とする。
- 日付は印刷を実行したクライアントのローカル日付を `YYYY/MM/DD` で表示する。
- 未設定値または未発射欄は空欄か `-` で表す。0点と未設定はデータ上で区別する。

### 2.3 スコア表記

| 表示             | 用途                           | 例              |
| ---------------- | ------------------------------ | --------------- |
| 小数点1桁        | 0.1点単位の得点                | `10.4`          |
| 整数得点         | 各発を整数化した合計           | `618`           |
| 小数・整数の併記 | 小数点合計を主、整数合計を補足 | **624.3** (618) |
| 順位             | 順位列                         | `1`, `2`, `3`   |
| 脱落位置         | Finalの脱落発数                | `E18`           |

内部DTOでは、Saika Laneの `Score` と同じく0.1点を整数1として扱う値がある。たとえば `104` は
表示上 `10.4` である。帳票境界で単位を暗黙に変換せず、DTOごとに下表の単位を守る。

## 3. ScoreSheet

### 3.1 目的とデータ選択

射座ごとの得点、着弾、シリーズ内訳を印刷する。Saika Laneの現行実装は次の順で対象ショットを
選択する。

1. 本射ショットが1発以上あれば、本射ショットだけを使う。
2. 本射開始前など、本射ショットがなければセッション内の全ショットを使う。
3. シリーズ番号の昇順にまとめ、各シリーズ内で1からショット番号を振り直す。

このフォールバックは試射内容の確認用であり、試射を公式記録に含める規則を意味しない。

### 3.2 公開DTO

`ScoreSheetDto`:

| フィールド        | 型                  | 単位・意味                         |
| ----------------- | ------------------- | ---------------------------------- |
| sessionId         | string              | セッションID                       |
| laneNumber        | number              | 射座番号                           |
| relay             | number              | 射群番号。`0` は未設定             |
| playerName        | string              | 選手名。現行Lane単体では空文字     |
| affiliation       | string              | 所属。現行Lane単体では空文字       |
| allShots          | ScoreSheetShotDto[] | 印刷対象ショット                   |
| seriesScores      | number[]            | シリーズ合計。0.1点を整数1とする   |
| totalScore        | number              | 全ショット合計。0.1点を整数1とする |
| totalIntegerScore | number              | 各発を整数化してから合計した値     |
| disciplineName    | string?             | 種目表示名                         |
| discipline        | Discipline          | 標的描画に使用する種目ID           |

`ScoreSheetShotDto`:

| フィールド   | 型             | 単位・意味                               |
| ------------ | -------------- | ---------------------------------------- |
| shotNumber   | number         | シリーズ内の1始まり連番                  |
| value        | number         | 0.1点を整数1とする得点                   |
| integerValue | number         | `floor(value / 10)`                      |
| seriesNumber | number         | 1始まりのシリーズ番号                    |
| x            | number \| null | 標的中心基準のX座標（mm）。ミスは `null` |
| y            | number \| null | 標的中心基準のY座標（mm）。ミスは `null` |

### 3.3 レイアウト

帳票は次の独立した機能ブロックで構成する。

```text
┌──────────────────────────────────────────────────┐
│ 種目名                              印刷日付      │
│ Lane: 射群-射座                                  │
│ 選手名 — 所属                                    │
├─────────────────────────────┬────────────────────┤
│ Result / Series / 点数別集計 │ 全着弾の標的図     │
├─────────────────────────────┴────────────────────┤
│ Series 1  標的図  整数合計 (小数合計)  5×2発     │
│ Series 2  標的図  整数合計 (小数合計)  5×2発     │
│ …                                                │
└──────────────────────────────────────────────────┘
```

- ヘッダーは種目、射群・射座、選手、所属、印刷日を表示する。
- サマリーは小数点合計、整数合計、シリーズ合計、10点から0点までの発数を表示する。
- 全着弾の標的図には通しのショット番号を描画する。
- 各シリーズは標的図、合計、5列×2行の最大10発を表示する。
- 表示枠は最低6シリーズ分を確保する。7シリーズ目以降もデータがあれば表示し、7シリーズ目の前で
  改ページする。
- 得点がないシリーズ枠と未発射セルは `-` を表示する。

### 3.4 現行制約

- Lane単体では大会名、会場、選手名、所属、射群が入力データに接続されていない。
- 印刷日は大会開催日ではなくクライアントの印刷日である。
- 画面上の印刷プレビューとプリンタードライバーの結果には差が出る場合がある。
- `totalScore` と `seriesScores` は0.1点単位の整数なので、表示時に10で割る必要がある。

## 4. ResultsListSheet（Director向け設計）

### 4.1 目的

Qualificationの成績を、種目全体または指定射群ごとに一覧表示する。順位は集計側で確定した値を
受け取り、帳票側では再計算・再順位付けしない。

### 4.2 入力モデル

`RankedResultDto` 相当:

| フィールド   | 型       | 意味               |
| ------------ | -------- | ------------------ |
| rank         | number   | 確定済み順位       |
| playerName   | string   | 選手名             |
| affiliation  | string   | 所属               |
| relayNumber  | number   | 射群番号           |
| seriesScores | number[] | シリーズごとの合計 |
| totalScore   | number   | 合計               |

### 4.3 レイアウト

```text
┌──────────────────────────────────────────────────────────┐
│ 種目名 / 第N射群                              印刷日付   │
├──────┬──────────┬──────────┬────┬────┬────┬──────┤
│ 順位 │ 選手名   │ 所属     │ S1 │ S2 │ …  │ 合計 │
├──────┼──────────┼──────────┼────┼────┼────┼──────┤
│ 1    │ 選手A    │ 所属A    │ …  │ …  │ …  │ …    │
│ 2    │ 選手B    │ 所属B    │ …  │ …  │ …  │ …    │
└──────┴──────────┴──────────┴────┴────┴────┴──────┘
```

- 射群指定がある場合だけ射群名を表示する。
- 順位は中央、名前と所属は左、得点は右に揃える。
- 合計は視認できる強さで表示する。
- 移植元設計ではシリーズ列が `S1`〜`S6` 固定である。公開実装時には競技定義から動的に生成する。
- 例示データには架空の名前・所属だけを使用する。

## 5. FinalResultSheet（Director向け設計）

### 5.1 目的と適用範囲

Finalの選手別ショット、累積点、脱落位置、同点決着を同じ帳票に表示する。ここに示す発数構成は
移植元設計時点のSaika表示モデルであり、特定競技の現行公式様式への適合を保証しない。実装では
競技定義を入力とし、主催団体の現行規則に合わせる。

### 5.2 入力モデル

`FinalResultData` 相当:

| フィールド        | 型       | 意味                      |
| ----------------- | -------- | ------------------------- |
| rank              | number   | 確定済み順位              |
| firingPointNumber | number   | 射座番号                  |
| playerName        | string   | 選手名                    |
| affiliation       | string   | 所属                      |
| stage1Shots       | number[] | 第1ステージの個別ショット |
| stage1Total       | number   | 第1ステージ合計           |
| stage2Shots       | number[] | 第2ステージの個別ショット |
| stage2Total       | number   | 第2ステージ合計           |
| totalScore        | number   | 最終合計                  |
| eliminatedAtShot  | number?  | 脱落が確定した発数        |
| remarks           | string   | `E18` などの備考          |

`ShootoffData` 相当:

| フィールド    | 型                                                     | 意味         |
| ------------- | ------------------------------------------------------ | ------------ |
| contestedRank | number                                                 | 対象順位     |
| participants  | Array<{ playerName, scores, result: winner \| loser }> | 参加者と結果 |

### 5.3 累積表示

移植元設計では、第1ステージ10発を5発ずつの2区間、第2ステージを2発ずつ最大7区間として表示する。

- 累積行は5、10、12、14、16、18、20、22、24発時点の合計を示す。
- 明細行は第1ステージを5発ずつ、第2ステージを2発ずつ縦に配置する。
- 脱落後の判定ポイントは `-` とし、視覚的に弱める。
- 脱落選手には `E##` を表示する。
- 帳票は受け取った順位の昇順で表示し、順位計算は行わない。
- Shootoffは入力がある場合だけ表示し、対象順位、各発、勝敗を示す。

### 5.4 レイアウト

```text
┌───────────────────────────────────────────────────────────┐
│ 大会名 / 種目名 / Final / 日付 / 会場                    │
├────┬──────┬──────┬──────────┬────────────────┬────┬────┤
│順位│氏名  │所属  │第1段階   │第2段階・脱落  │合計│備考│
│    │      │      │ 5 / 10   │12 … 24         │    │    │
├────┼──────┼──────┼──────────┼────────────────┼────┼────┤
│ …  │選手A │所属A │累積/各発 │累積/各発       │ …  │E## │
└────┴──────┴──────┴──────────┴────────────────┴────┴────┘
│ Shootoff（データがある場合のみ）                          │
└───────────────────────────────────────────────────────────┘
```

### 5.5 移植元設計時点の未完了事項

- Shootoffデータと印刷画面の連携を統合テストする必要がある。
- 射座番号列、大会名、会場などの入力経路を確定する必要がある。
- 競技定義の変更に対して発数列を動的に生成する必要がある。
- 順位確定、同点処理、失格・棄権の表記は帳票外のドメイン処理として定義する必要がある。

## 6. 受け入れ条件

- 同じDTOからプレビューと印刷で同じ得点・順位が出る。
- 0点、未発射、ミス、未設定値が混同されない。
- 小数点合計と整数合計が、それぞれの定義どおりに再現できる。
- シリーズ、選手、ページ境界で文字や行が欠落しない。
- 実在選手のデータをfixture、スクリーンショット、文書例に使用しない。
- 公式帳票との一致や認証済みであることをUI・文書・配布物で表示しない。
